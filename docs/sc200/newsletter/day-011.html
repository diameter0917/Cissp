03 — 🖥️ 核心概念

Standalone 與 Embedded：一個大腦、兩種上場方式

Security Copilot 是橫跨整個 Microsoft 安全生態系的生成式 AI 助手，底層是同一個服務、同一份容量，但有兩種「上場方式」，考題最愛考你選哪一種：

比較面Standalone 獨立體驗Embedded 內嵌體驗
入口securitycopilot.microsoft.com 專屬入口嵌在各產品內：Defender 入口、Microsoft Entra、Intune、Purview 等的 Copilot 窗格／卡片
形態完整聊天工作台：session（工作階段）、promptbook、外掛管理、用量儀表板跟著當下畫面走：事件頁給摘要、搜捕頁生 KQL、政策頁做分析
適用情境跨產品長調查、串多個資料來源、執行與建立 promptbook、所有管理設定不離開工作畫面的即時輔助：一鍵摘要、引導式回應、就地分析
典型使用者Tier 2／3 深度調查者、Copilot 管理者Tier 1 分診分析師、各產品的日常操作者

Embedded 在 Defender 入口的實戰能力，就是考綱點名的那幾件事：事件摘要（把跨產品警示組成攻擊敘事）、引導式回應（guided response）（依事件內容列出建議回應動作，逐步帶你執行）、指令碼與檔案分析（把混淆的 PowerShell／Base64 還原成白話）、進階搜捕的 KQL 輔助生成（自然語言轉查詢），以及 Intune 端的政策分析與 Entra 端的風險使用者摘要。以 KQL 輔助為例，你在進階搜捕輸入一句自然語言：

// 提示：「過去 7 天有哪些裝置執行過 Base64 編碼的 PowerShell？」
// Copilot 產生的查詢：
DeviceProcessEvents
| where Timestamp > ago(7d)
| where FileName =~ "powershell.exe"
| where ProcessCommandLine has "-enc"
| summarize Executions = count() by DeviceName, AccountName
| sort by Executions desc
Copilot 負責把需求翻譯成 KQL，但「審查再執行」是你的責任——考題會考這個觀念：生成的查詢應先確認資料表與篩選條件是否符合意圖，而不是盲目執行。這也是課程 W1 先教 KQL 的原因：看得懂，AI 才是副駕駛而不是代駕。
💼 實戰情境：用 Copilot 走完一次釣魚事件調查

上午 10:20，事件佇列跳出高嚴重性事件：「使用者回報的網路釣魚郵件，關聯端點上的可疑 PowerShell」。你是 Tier 1，全程沒離開 Defender 入口：第一步「事件摘要」——打開事件即見 Copilot 摘要卡片：釣魚郵件→使用者開啟附件→附件產生 PowerShell 下載程序，涉及 1 個信箱、2 台裝置，攻擊敘事一分鐘讀完。第二步「指令碼分析」——對警示裡那串混淆的 PowerShell 按下分析，Copilot 還原 Base64：這是一支下載器，會連往外部網址抓取第二階段酬載。第三步「KQL 輔助」——你用自然語言問「還有哪些裝置執行過相同雜湊的檔案」，確認影響範圍就是那 2 台。第四步「引導式回應」——依 guided response 建議逐項執行：隔離 2 台裝置、軟刪除全租用戶同主旨郵件、封鎖寄件網域、要求使用者重設密碼。收尾前再請 Copilot 產生事件報告貼進工單。原本要跨三個入口、翻兩份 SOP 的調查，一個畫面走完——而下一節你會看到，這條流程未來甚至可以交給 agent 自己跑。

04 — 💰 核心概念

SCU：Security Copilot 的水電表

Security Copilot 不是按人頭賣授權，而是賣算力：計價單位叫 SCU（Security Compute Unit）。你在 Azure 訂用帳戶下建立一個「容量（capacity）」資源（從 Azure 入口或 Security Copilot 入口都能建），選定地理區域，設定每小時要佈建幾顆 SCU——之後按小時計費，不管當小時有沒有用滿。最低 1 SCU，官方建議從 3 SCU 起步再依用量調整；佈建量可以隨時調高調低，變更在一小時內生效，所以「上班時段調高、下班調低」是合法的省錢策略。

每次提示消耗多少 SCU，取決於任務複雜度——跑一本 promptbook 或一次深度事件調查，吃的算力遠多於一句簡單提問；agents 執行任務同樣消耗 SCU。當小時的佈建量用完會發生什麼？沒有配套的話，提示會被拒絕，直到下一個小時容量重置。這就是 2026 新考點 overage（超額單位）登場的理由：啟用後，佈建量用罄改以「用多少付多少」的 overage SCU 繼續服務，單價比佈建式高，可設定無上限或月上限——本質是拿單價換彈性，避免關鍵調查在月底斷線。用量則靠獨立入口的用量監控儀表板掌握：能看每小時消耗、依使用者／功能／外掛切分，並在逼近容量時收到通知。

🎯 考點聚焦：SCU 佈建題的三種問法

第一種問「症狀」：分析師抱怨提示被拒或月底特別容易失敗——診斷是佈建容量不足，解法是調高 SCU 或啟用 overage。第二種問「成本最佳化」：要避免中斷、又不想整月按尖峰量佈建——最佳答案是基準佈建＋啟用 overage（或按時段調整佈建量），選「全天按尖峰佈建」是浪費錢的陷阱。第三種問「誰能佈建」：建立容量需要 Azure 訂用帳戶上的 Owner／Contributor 權限——這是 Azure RBAC 的事，跟 Copilot 自己的 owner／contributor 角色是兩回事（第 07 節細講，考題超愛混著考）。另外記住：SCU 是佈建式＋按小時計費，選項寫「按使用者授權計費」「按查詢次數買斷」都是干擾項。

05 — 🔌 核心概念

外掛、知識庫與 promptbooks：餵料與食譜

Copilot 本身不儲存你的安全資料，它的「知識」來自外掛（plugins）——每個外掛就是一條伸進資料來源的手。三大類：Microsoft 外掛（Defender XDR、Microsoft Sentinel、Microsoft Entra、Intune、MDTI＝Microsoft Defender Threat Intelligence、Purview、自然語言轉 KQL 等，多數隨授權自動可用）；非 Microsoft 外掛（ServiceNow、VirusTotal、AbuseIPDB 這類第三方服務，通常要填 API 金鑰）；自訂外掛（用 OpenAPI 規格把自家內部系統接進來）。另外還有檔案上傳知識庫（knowledge base）：把公司的事件回應 SOP、網路架構文件上傳，Copilot 回答時就能引用你組織自己的脈絡——這是「讓 AI 講你家的話」的關鍵功能，owner 可以整體開關檔案上傳能力。

權限鐵律：Copilot 透過外掛查資料時，用的是你的身分（on-behalf-of）。你在 Sentinel 沒讀取權限，Copilot 也替你查不到——它不會幫任何人越權。考題問「為什麼某分析師的 Copilot 查不到 Sentinel 事件」，先想他本人的資料權限，而不是 Copilot 設定。

外掛解決「資料從哪來」，promptbook 則解決「調查怎麼跑」：它是把一連串提示打包成可重複執行的工作流程——你可以把它想成食譜，輸入參數（如事件編號、指令碼內容）後逐步執行。內建 promptbook 涵蓋 SOC 最常見的場景，也可以從自己的 session 把有效的提示序列存成自訂 promptbook 分享給團隊：

常用 promptbook輸入適用場景
事件調查（Incident investigation）事件編號Tier 1／2 接手事件時產出摘要、影響實體、回應建議的標準首查
可疑指令碼分析（Suspicious script analysis）指令碼內容還原混淆的 PowerShell／Bash，解釋行為並評估意圖
威脅執行者設定檔（Threat actor profile）執行者名稱產出威脅情資摘要：慣用手法、目標產業、相關 IoC
弱點影響評估（Vulnerability impact assessment）CVE 編號摘要弱點原理與緩解建議，評估對環境的影響
自訂 promptbook自訂參數把團隊反覆使用的調查流程標準化，新手也能跑出資深品質
06 — 🤖 核心概念

Agentic AI：從「你問我答」到自主分診

2026 新考點 2026 考綱最有時代感的一塊：Copilot agents。前面講的一切——提示、promptbook——都是「你發球、AI 回球」；agentic AI 則是把整個任務交付出去：agent 會自主規劃步驟、呼叫工具與資料、產出結論與理由，人類保留最終決定權（human-in-the-loop）。最具代表性的是自主分診 agent 概念：以 Phishing Triage Agent 為例，使用者回報的釣魚郵件動輒每天數百封，其中九成是誤報，它自動逐封調查——分析寄件者、連結、附件行為——給出真偽判定與白話理由，分析師只覆核判定並在不同意時給回饋，agent 會從回饋中學習調整後續判準。這正是它與傳統自動化規則（automation rule）的本質差異：規則按固定條件動作，agent 會推理、會解釋、會迭代。

其他代表性 agents 也認個臉：Conditional Access Optimization Agent（Entra：盯著新使用者與應用程式，主動建議條件式存取政策的涵蓋缺口）、Vulnerability Remediation Agent（Intune：協助排定弱點修補優先序）、Threat Intelligence Briefing Agent（自動產出與你環境相關的威脅情資簡報）。管理面三件事要記：agents 消耗 SCU（自主調查不是免費的，佈建容量要把 agent 用量算進去）；agents 有自己的識別與權限，依最小權限原則只授與完成任務所需的存取；agents 的每一步行動有紀錄可稽核，出錯時能回溯它「為什麼這樣判」。

07 — 🔐 核心概念

權限模型與稽核隱私：三層權限別打架

Security Copilot 的權限題幾乎都在考「三層分清楚」：第一層 Azure RBAC——佈建 SCU 容量需要 Azure 訂用帳戶的 Owner／Contributor，首次設定（first-run setup）由 Entra 的 Global Administrator 或 Security Administrator 執行。第二層 Copilot 平台角色——Copilot owner 管平台：外掛開放範圍、檔案上傳開關、用量監控、資料共用設定；Copilot contributor 用平台：建立 session、執行 promptbook、日常調查。第三層資料存取——就是第 05 節的鐵律：on-behalf-of，回應內容受使用者本人在各產品的權限限制。

🎯 考點聚焦：最小權限選角

題目給角色與任務，選「剛好夠用」的權限：SOC 分析師要用 Copilot 調查、跑 promptbook——Copilot contributor，給 owner 就是過度授權；要管理外掛與檔案上傳設定——Copilot owner；要建立或調整 SCU 容量——Azure 訂用帳戶的 Owner／Contributor（Copilot 角色辦不到）。看到「直接給 Global Administrator 比較方便」這種選項一律淘汰——SC-200 的最小權限哲學與 Day 4 統一 RBAC 一脈相承。

最後是稽核與隱私——提示（prompt）與回應如何被處理：session 內容屬於客戶資料，儲存在租用戶所在地理區域，不會拿去訓練基礎模型；管理者可透過稽核機制（與 Microsoft Purview 稽核整合）追查誰在何時下了什麼提示；owner 可決定是否參加選擇性的資料共用（協助改善產品）。

🛡️ 面對「AI 會不會把我們的機密學走」這類質疑，標準答案三件套：客戶資料不用於訓練基礎模型、資料留在租用戶地理區域、提示與回應可稽核。這組敘述本身就可能入題。

影片沒講到的考綱角落

EP2 以功能示範為主，且錄製時間早於 2026 考綱定稿，下列項目影片著墨少或根本沒有，請以本文為準：

  • Copilot agents 全家福：Phishing Triage、Conditional Access Optimization、Vulnerability Remediation 等 agents 與「自主分診＋人工覆核＋回饋學習」概念是考綱明文的 agentic AI 重點，影片幾乎未涵蓋（見第 06 節）。
  • 檔案上傳知識庫：把組織自己的 SOP 與文件餵給 Copilot 引用，以及 owner 端的開關管理。
  • 稽核與隱私敘述：提示與回應的儲存位置、不用於訓練基礎模型、Purview 稽核整合——管理面必背三件套。
  • 與自動化的分界：考題可能拿 Sentinel 自動化規則、劇本（Playbook）當干擾項——固定條件的自動動作用規則與劇本；需要推理、解釋與回饋學習的分診交給 agent。這條分界線 W4 講自動化時會再回頭印證。

看正解與解析
正解：A

SCU（Security Compute Unit）是佈建式容量、按小時計費，當小時的佈建量用罄時提示就會被拒絕，直到下一小時容量重置。overage（超額單位）正是為此設計：啟用後佈建量用完會改以「用多少付多少」的超額 SCU 繼續服務，單價較高但可設定月上限，本質是拿單價換彈性。因此成本最佳化題的最佳答案是「基準佈建＋啟用 overage」（或依時段調整佈建量），既避免關鍵調查斷線，也不必整月按尖峰付費。

  • B：整月按尖峰佈建可以避免被拒，但夜間容量完全閒置仍照小時計費，是成本最佳化題的典型浪費陷阱，也違反管理層的條件。
  • C：Security Copilot 不是按人頭賣授權，而是賣算力：以 SCU 佈建容量、按小時計費。「按使用者授權計費」是常見的干擾敘述。
  • D：standalone 與 embedded 只是同一個服務的兩種上場方式，底層共用同一份 SCU 容量，換介面並不會增加可用算力。

QUESTION 2 · D1-0062
A tier-1 analyst opens the Security Copilot pane on an incident page in the Microsoft Defender portal and asks for related Microsoft Sentinel incident details. Copilot returns nothing for that analyst, while a colleague in the same tenant receives full results from the identical prompt. What should you check first?
（一位第一線分析師在 Microsoft Defender 入口網站的事件頁面開啟 Security Copilot 窗格，詢問相關的 Microsoft Sentinel 事件細節。Copilot 對這位分析師沒有回傳任何內容，但同一租用戶的同事用完全相同的提示卻得到完整結果。你應該優先檢查什麼？）
A. Whether the Security Copilot capacity has enough provisioned SCUs for the current hour.
Security Copilot 容量在當前小時是否還有足夠的佈建 SCU。
B. Whether the analyst has the required Microsoft Sentinel data permissions, because plugins query data on behalf of the signed-in user.
該分析師本人是否具備所需的 Microsoft Sentinel 資料權限——外掛是以登入使用者的身分（on-behalf-of）查詢資料。
C. Whether the analyst has been assigned the Copilot owner role.
該分析師是否已被指派 Copilot owner 角色。
D. Whether the Microsoft Sentinel plugin has been turned on in the standalone portal.
Microsoft Sentinel 外掛是否已在獨立入口中啟用。
看正解與解析
正解：B

權限鐵律：Copilot 透過外掛（plugin）查資料時，用的是「你的身分」（on-behalf-of）——使用者在 Microsoft Sentinel 沒有讀取權限，Copilot 也替他查不到，它不會幫任何人越權。題幹的關鍵線索是「同一租用戶、同一提示，同事拿得到結果」，代表容量、外掛設定與服務本身都正常，差別只在使用者本人的資料存取權。

  • A：容量不足時的症狀是提示被直接拒絕，而且會同時影響租用戶內所有使用者；同事能正常取得結果即可排除這個原因。
  • C：Copilot owner 是管平台的角色（外掛開放範圍、檔案上傳開關、用量監控），與能不能查到 Sentinel 資料無關；為了取得資料而給 owner 是過度授權。
  • D：外掛若沒有啟用，同事也會查不到；同事拿得到完整結果，代表 Microsoft Sentinel 外掛在租用戶層級是開著的。

QUESTION 3 · D1-0063
Your SOC wants every analyst to run the same five-step sequence of Security Copilot prompts whenever an obfuscated PowerShell script is found, so that junior analysts produce output of the same quality as senior analysts. The sequence must be reusable, parameterized, and shareable across the team. What should you create?
（貴 SOC 希望每次發現混淆的 PowerShell 指令碼時，所有分析師都執行同一組五個步驟的 Security Copilot 提示序列，讓資淺分析師也能產出與資深同等品質的成果。這組序列必須可重複執行、可帶入參數，並能分享給整個團隊。你應該建立什麼？）
A. A Microsoft Sentinel automation rule that runs when an incident is created.
在事件建立時執行的 Microsoft Sentinel 自動化規則。
B. A Copilot agent that has its own identity and permissions.
具備自己的識別與權限的 Copilot agent。
C. A custom promptbook saved from a Security Copilot session and shared with the team.
從 Security Copilot 工作階段（session）存成自訂 promptbook，並分享給團隊。
D. A knowledge base file upload that contains the team's incident response SOP.
上傳包含團隊事件回應 SOP 的檔案作為知識庫（knowledge base）。
看正解與解析
正解：C

promptbook 就是把一連串提示打包成可重複執行的工作流程——像食譜一樣，輸入參數（事件編號、指令碼內容等）後逐步執行。內建 promptbook 已涵蓋事件調查、可疑指令碼分析、威脅執行者設定檔、弱點影響評估等常見場景；團隊自有的調查流程則可從有效的 session 存成自訂 promptbook 分享出去，正是題幹要的「標準化、可重複、新手也能跑出資深品質」。

  • A：自動化規則是 Microsoft Sentinel 事件端的觸發機制（指派、變更狀態、執行劇本），不會執行 Security Copilot 的提示序列。
  • B：agent 是把整個任務交付出去、由 AI 自主規劃與執行的機制，適用於自主分診等場景；本題要的是分析師手動依序執行的標準流程，用 agent 屬於過度設計。
  • D：檔案上傳知識庫解決的是「Copilot 回答時要引用組織自身脈絡（SOP、架構文件）」，它提供內容給回應參考，但不會定義一組可重複執行的提示步驟。

QUESTION 4 · D1-0064
Your SOC receives several hundred user-reported phishing messages every day, and roughly 90 percent of them turn out to be harmless. You need a solution that investigates each report on its own, states a verdict with a plain-language justification, and adjusts its judgement when analysts disagree with the verdict during review. What should you adopt?
（貴 SOC 每天收到數百封使用者回報的釣魚郵件，其中約九成最後證實無害。你需要一套解決方案：能自行逐封調查、以白話說明理由給出真偽判定，並在分析師覆核時不同意判定後調整後續判準。你應該採用什麼？）
A. A Microsoft Sentinel automation rule that closes incidents matching a fixed condition.
以固定條件關閉相符事件的 Microsoft Sentinel 自動化規則。
B. A logic-app playbook that is triggered when the incident is created.
在事件建立時觸發的 Logic Apps 劇本（Playbook）。
C. A custom promptbook that an analyst runs for each reported message.
由分析師針對每一封回報郵件手動執行的自訂 promptbook。
D. The Phishing Triage Agent, a Security Copilot agent whose verdicts analysts review and give feedback on.
Phishing Triage Agent——一個由分析師覆核判定並提供回饋的 Security Copilot agent。
看正解與解析
正解：D

題幹三個條件（自主逐封調查、給出可解釋的判定理由、能從分析師回饋中學習）正是 agentic AI 與傳統自動化的分界線：規則按固定條件動作，agent 會推理、會解釋、會迭代。Phishing Triage Agent 自動分析寄件者、連結與附件行為，給出真偽判定與白話理由，分析師只需覆核並在不同意時提供回饋，agent 會據以調整後續判準（human-in-the-loop）。管理面要記得：agent 會消耗 SCU、有自己的識別與最小權限、每一步行動都可稽核。

  • A：自動化規則依固定條件執行固定動作，不會逐封推理、不會解釋理由，也無法從分析師的回饋中學習。
  • B：劇本是預先寫好的固定工作流程（Logic Apps），適合可明確定義步驟的自動回應動作；它不具備自主判斷與回饋學習能力。
  • C：promptbook 仍屬於「你發球、AI 回球」：需要分析師逐封手動執行，每天數百封的量無法消化，也沒有回饋學習機制。

QUESTION 5 · D1-0065
A tier-1 analyst must obtain an incident summary and guided response suggestions without leaving the incident page in the Microsoft Defender portal. A tier-3 investigator must run a multi-step promptbook that spans several products and must also review capacity usage. Which Security Copilot experience should each of them use?
（一位第一線分析師必須在不離開 Microsoft Defender 入口網站事件頁面的情況下取得事件摘要與引導式回應（guided response）建議；一位第三線調查者則必須執行跨多個產品的多步驟 promptbook，並檢視容量用量。這兩個人分別應該使用哪一種 Security Copilot 體驗？）
A. Both should use the standalone Security Copilot portal.
兩人都使用 Security Copilot 獨立（standalone）入口。
B. Both should use the embedded Security Copilot experience.
兩人都使用內嵌（embedded）體驗。
C. The tier-1 analyst should use the standalone portal, and the tier-3 investigator should use the embedded experience.
第一線分析師使用獨立入口，第三線調查者使用內嵌體驗。
D. The tier-1 analyst should use the embedded experience, and the tier-3 investigator should use the standalone portal.
第一線分析師使用內嵌體驗，第三線調查者使用獨立入口。
看正解與解析
正解：D

同一個大腦、兩種上場方式：內嵌體驗跟著當下畫面走，在 Defender 入口的事件頁提供事件摘要、引導式回應、指令碼分析與 KQL 輔助生成，適合不離開工作畫面的第一線分診；獨立入口（securitycopilot.microsoft.com）是完整的聊天工作台，提供 session、promptbook 執行與建立、外掛管理與用量儀表板，適合跨產品長調查與所有管理設定。因此第一線用內嵌、第三線用獨立入口。

  • A：全部改用獨立入口會讓第一線分析師被迫離開事件頁面，失去內嵌體驗「就地摘要與引導式回應」的價值。
  • B：內嵌體驗跟著各產品畫面走，不提供 promptbook 的完整執行與建立、外掛管理與用量儀表板，無法滿足第三線調查者的需求。
  • C：兩者剛好對調：需要就地輔助的是第一線分診，需要完整工作台與管理畫面的是第三線深度調查者。
