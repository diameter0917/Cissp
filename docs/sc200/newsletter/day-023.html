01 — 📌 本日導讀

從「查得到」升級成「想得到」

前兩天你已經會用 Microsoft Sentinel 的搜捕介面跑查詢、存書籤、開 Livestream——那是手；今天補上腦：這個查詢究竟是為了回答什麼問題？D3「執行威脅搜捕」占 20–25%，考題不問按鈕在哪，而是丟給你一份威脅情報或一個 ATT&CK 技術，問下一步該搜捕什麼、範圍怎麼訂、結果記在哪。三條主線：三種驅動方式各自從哪裡起跑、MITRE ATT&CK 怎麼當地圖用、筆記本（Notebook）何時才划算。

學習目標（對應官方考綱 D3「執行威脅搜捕」）：
  • ☐ 說明搜捕與事件回應、警示分診的差別，並定義可驗證的假說（對應 hunt for threats by using Microsoft Sentinel）

03 — 🧭 三種驅動方式

搜捕不是只有一種跑法

「威脅搜捕」在考題裡有三種面貌，起跑點不同，搞混就會選錯工具。

驅動方式起點怎麼跑產出侷限
情資驅動
（IoC）		具體指標：雜湊、網域、IP、寄件者指標放進監視清單（Watchlist）或威脅情報，跨表比對並回溯歷史明確的是／否：出現過沒、在哪台、何時第一次只抓得到已知；對手換基礎設施就失效
假說驅動一句可驗證的推測，多半來自 ATT&CK 技術或威脅模型拆成可觀察特徵 → 選資料表 → 訂時間窗 → 查詢 → 依結果轉向成立／不成立／資料不足，外加新偵測構想與能見度缺口吃知識與時間；寫太大跑不完
異常驅動統計或機器學習指出的離群：UEBA 分數、異常規則從離群反推情境：平常長什麼樣、這次哪裡不同、有無旁證值得升級的少數異常，與調整基準線的依據離群不等於惡意，需環境知識篩

成熟 SOC 是三者接力：情資驅動找到一台中招主機 → 假說驅動問「同一手法還有誰中」→ 異常清單再變成下一輪假說的靈感。今天主攻中間這段。

🎯 考點聚焦
「這是搜捕嗎」只有一個判準：起點是不是「先前未被偵測到」的東西。題幹寫「佇列出現高嚴重性事件，請調查」→ 那是分診；寫「懷疑有尚未觸發警示的行為，請主動尋找」→ 才是搜捕。陷阱選項常把「調降規則門檻」或「檢視自動調查結果」包裝成搜捕，兩者都從既有警示出發。
04 — 🧪 假說怎麼生出來

四個來源，一個句型，三種結局

最卡的一步是「我知道要寫假說，可是要假設什麼？」假說有四個穩定來源：威脅情報（某群組用合法遠端管理工具做持續性 → 我這裡有沒有非 IT 主機裝了這類工具）、ATT&CK 技術（挑一個沒有規則覆蓋的格子當題目）、環境弱點（共用本機管理員密碼、沒 MFA 的服務帳號）、近期事件（上次沒查完的線頭）。

假說句型：如果〔對手行為／ATT&CK 技術〕正在我的環境發生，那麼在〔資料表／訊號來源〕應可觀察到〔具體特徵〕，範圍限定〔時間窗〕與〔資產範圍〕。
例：如果有人用 DCSync（T1003.006）竊取憑證，目錄複寫紀錄中應出現「非網域控制站帳號發起複寫請求」，範圍是近 30 天、全部網域控制站。

寫完拿影片那五條檢查，最常被違反的是「範圍夠窄」——「找出所有橫向移動」不是假說，是願望。也要接受三種結局都算成功：成立（存書籤、升級成事件）、不成立（存下查詢並記錄「查過、目前乾淨」）、資料不足（要看的欄位根本沒收，等於挖出能見度缺口）。沒抓到人不等於白做。

🎯 考點聚焦
四個選項都像合理假說時怎麼刷：依序刪掉——沒有時間窗或範圍的、用現有資料無法證實或推翻的、與威脅模型無關的、大到跑不完的。剩下的通常是「限定時間窗＋限定資產＋指名一個技術」那個。另一轉折題：查完什麼都沒有，下一步？正解多半是保存查詢並記錄結論。
🛡️ 實戰情境：一次完整的假說驗證（DCSync）

週一 09:40 情資進來：某鎖定製造業的群組慣用手法是先取得有複寫權限的服務帳號，再用 DCSync 拉出全網域雜湊。你們正是製造業，對得上威脅模型。

  1. 寫假說（09:50）：即上面那句 DCSync 假說，五條檢核全過。
  2. 選資料（09:55）：首選 Microsoft Defender for Identity（MDI）的身分目錄事件；只有 Windows 安全性事件記錄時就看物件存取事件（4662）與複寫控制存取碼。先確認資料真的有在收，否則結論只會是「資料不足」。
  3. 第一次查詢（10:05）：看有誰做過複寫，把網域控制站電腦帳號排除。
IdentityDirectoryEvents
| where Timestamp > ago(30d)
| where ActionType == "Directory Services replication"
| where AccountName !endswith "$"
| summarize FirstSeen = min(Timestamp), LastSeen = max(Timestamp),
            Attempts = count(), Sources = make_set(DeviceName, 10)
        by AccountName, AccountDomain
| order by Attempts desc

30 天時間窗呼應假說；只留「目錄服務複寫」動作；!endswith "$" 濾掉電腦帳號，因為網域控制站彼此複寫是正常的；summarize 算出首見／末見、次數與來源主機——首見時間最關鍵，它區分「一直都有」與「這週才冒出來」。

  1. 結果（10:12）：svc-backup 十四個月來每天出現、來源固定是備份伺服器，屬於基準線；svc-print 只在上週四凌晨 02:11 出現 3 次，來源是財務部工作站——印表服務帳號、半夜、從使用者工作站發起複寫，三個條件同時不合理。
  2. 轉向（10:20）：pivot 到那台工作站，看同時段前後發生了什麼。
let SuspectWindow = datetime(2026-08-13 01:30) .. datetime(2026-08-13 03:30);
DeviceProcessEvents
| where Timestamp between (SuspectWindow)
| where DeviceName startswith "FIN-WS"
| project Timestamp, DeviceName, AccountName, FileName,
          InitiatingProcessFileName, ProcessCommandLine
| order by Timestamp asc

用 let 命名時間區間再以 between 套用，是轉向時最省事的寫法；只投影必要欄位讓時間軸讀得順，父程序與命令列往往就是判斷惡意與否的關鍵。

  1. 結論（10:35）：複寫前 6 分鐘，有人以遠端管理工具在該機啟動了一個從暫存目錄執行的程式，父程序是瀏覽器下載。假說成立。
  2. 收尾（10:40）：關鍵結果列存成書籤，對應實體（svc-print、FIN-WS-042），戰術標憑證存取、技術標 T1003.006，升級成事件交二線；第一段查詢存成搜捕查詢並排程每日重跑。順帶收穫是建立了「哪些帳號可以合法複寫」的基準線。
05 — 🗺️ ATT&CK 當地圖

戰術是目的，技術是手法

ATT&CK 是對手行為的公開知識庫，三層結構常被拿來出分辨題：戰術（tactic）＝對手為什麼做，是階段性目的（初始存取、持續性、憑證存取…），企業矩陣共 14 個，Sentinel 的規則與書籤標的就是這層；技術（technique）＝怎麼做，有 T 編號（T1003 OS Credential Dumping）；子技術是更細作法（T1003.006 DCSync）；程序則是某對手的實際實作。

MITRE ATT&CK 涵蓋率檢視把矩陣畫在你的環境上：顏色深淺代表有多少偵測對應到該技術，並可切換兩種來源——已啟用的分析規則與規則範本及搜捕查詢，兩者差距就是「馬上補得起來的缺口」。缺口也分兩種：沒資料（連接器沒接、記錄層級沒開）要補資料源，有資料沒規則則啟用範本或自己寫。

另一個實務重點：搜捕成果要自己標上去。影片建書籤與搜捕查詢時都做了對應實體與選戰術兩件事；沒標的查詢不會進涵蓋率統計，那張圖也就退化成裝飾品。

ATT&CK 戰術對手目的訊號來源典型搜捕假說
初始存取取得第一個立足點郵件事件、身分登入、VPN近 7 天有無使用者自從未出現的國家成功登入
持續性重開機後仍活著登錄機碼、排程工作、服務建立近 30 天有無非 IT 帳號建立自動啟動項目或信箱委派
憑證存取拿到帳密或雜湊身分目錄事件、LSASS 存取近 30 天有無非網域控制站帳號發起目錄複寫（見 §04）
橫向移動從一台擴散到多台登入事件、遠端服務、SMB／WMI近 7 天有無帳號 1 小時內登入 5 台以上沒登過的主機
命令與控制維持外部通道網路連線、DNS、Proxy近 14 天有無主機對同一外部位址呈固定間隔的信標連線
外洩把資料帶走雲端應用活動、上傳流量近 30 天有無帳號於非上班時段大量下載再上傳個人雲端
🎯 考點聚焦
戰術 vs 技術：訣竅是問「對手想達成什麼（戰術）」與「用什麼手段（技術）」。「傾印 LSASS 記憶體取得雜湊」→ 戰術是憑證存取、技術是 OS Credential Dumping、子技術是 LSASS Memory。陷阱是把「橫向移動」當技術、「Pass-the-Hash」當戰術，方向剛好相反。另一組必背：涵蓋率檢視回答「我對哪些技術有偵測」，不是「我被哪些技術打過」；問「如何找出偵測缺口」→ 選它，不是活頁簿。
06 — 📓 筆記本何時划算

Notebook 不是更炫的查詢框

筆記本就是 Jupyter：文字與可執行程式碼交錯的文件，在 Sentinel 裡跑 Python，透過 Log Analytics 的 API 讀你的資料。兩個名字要記住：KQLMagic（在筆記本裡直接寫 KQL 的包裝）與 MSTICPy（微軟的資安調查 Python 工具集，含情報查詢、GeoIP、時間序列分析與視覺化）。

重點不是「它能做什麼」，而是何時值得付這個成本——它要 Azure Machine Learning 工作區與運算資源（計費）、要 Python 能力、還要維護程式碼。判準很簡單：KQL 查詢框做得到的就別開筆記本。真正划算的有四類：機器學習與統計（分群、離群與信標偵測、時間序列分解）、外部資料富化（逐個 IP 查 Whois、GeoIP、多家情報再併回同一張表）、跨來源合併（Sentinel 資料＋資產清冊、HR 名單）、可重複的調查劇本（換個參數重跑整套流程，過程天然就是紀錄）。

工具核心用途主要使用者選它的時機
搜捕查詢（KQL）互動式提問與轉向全體分析師問題能用一段 KQL 表達——絕大多數情況
劇本（Playbook）自動化與修復動作SOC 工程師、分析師要「做動作」：通知、開單、封鎖、隔離
活頁簿（Workbook）視覺化與儀表板分析師、SOC 主管要給人持續看的圖表與趨勢
筆記本（Notebook）深度分析與彈性調查威脅搜捕者、二三線分析師、資料科學家機器學習、外部富化、跨來源合併、可重複的調查流程

建立方式兩條：從 Sentinel 筆記本頁面挑範本（需連結 Azure ML 工作區與運算叢集），或在 Visual Studio Code 建 Jupyter Notebook 再接回來。2026 新考點 data lake 的筆記本走 Sentinel 的 VS Code 擴充功能加 MCP（Model Context Protocol）伺服器，直接對 data lake 資料源探索——這條路線與 Sentinel Graph 是明天的主題。

🎯 考點聚焦
工具四選一怎麼刷：題幹出現 apply machine learning、enrich with GeoIP or Whois、combine Sentinel data with external datasets → 筆記本；automatically notify / block / isolate → 劇本；dashboard for management → 活頁簿；「快速確認這個雜湊有沒有出現過」→ 一段搜捕查詢就好。另一常錯點：使用筆記本的前置作業是 Azure ML 工作區與運算資源，不是「啟用 UEBA」或「建立監視清單」。
07 — 🪜 成熟度與紀錄

讓有效的假說變成資產

搜捕做不起來的團隊，多半不是查詢寫不好，而是每次都從零開始。成熟度階梯：臨時起意 → 有來源（依情資或 ATT&CK 挑題）→ 可重複（假說與查詢存下來，別人照著能重跑）→ 排程化 → 自動化（變成規則，或用結果維護監視清單）。

何時把假說變成規則？三條件同時成立時升級為排程分析規則：訊噪比夠好、邏輯能穩定用 KQL 表達、值得 24 小時盯。若只是定期回顧或要跨很長時間，走 data lake 的 KQL 作業或搜尋作業；訊噪比差但有價值的，留在搜捕查詢並排人工複查。

紀錄要留什麼？書籤存的是查詢＋結果列＋實體對應＋戰術標記；一次搜捕結束，紀錄至少要有假說原文、資料範圍與時間窗、用過的查詢、結果判定與後續動作。「不成立」的同樣要留——半年後有人問「查過 DCSync 嗎」，你要答得出「查過，範圍 30 天，乾淨」。

💡 搜捕的三種產出都要交付：(1) 發現——書籤與升級的事件；(2) 新偵測——排程規則、自訂偵測或搜捕查詢；(3) 缺口——資料沒收、記錄層級不足、涵蓋率空白格。第三項最常被漏掉，卻是考題問「搜捕的價值」的標準答案之一。

EP10 略過、考題卻會碰的

  • 搜捕查詢範本客製（考綱 customize content gallery hunting queries）：社群查詢的正確用法是複製後改成自己的資料表與門檻（如排除已知服務帳號），再存成自己的查詢並標戰術，而不是原封不動跑完抱怨誤報高。
  • Hunts 與書籤的關係：hunt 把假說敘述、狀態（進行中／已驗證／已推翻）、多個查詢、書籤與筆記收在同一容器並指派負責人。問「如何追蹤多人協作的搜捕」→ 建立 hunt，不是各存各的書籤。
  • 進階搜捕 vs Sentinel 搜捕：前者查 XDR 自己的表（預設 30 天）、可直接做成自訂偵測並附回應動作；後者查工作區全部資料源、可回溯更久。跨端點＋身分＋郵件的快問快答走進階搜捕，含第三方記錄或要拉長時間走 Sentinel。
  • 筆記本的權限與成本：需 Azure ML 工作區與 Sentinel 讀取權限；運算執行個體不用要停掉否則持續計費；MSTICPy 的工作區 ID 與 API 金鑰放設定檔，不該寫死在程式碼區塊。
  • Security Copilot 協助搜捕 2026 新考點：可用自然語言生成 KQL 搜捕查詢、摘要結果。定位照舊——它加速把想法變成查詢，假說品質與是否升級仍由分析師負責。
