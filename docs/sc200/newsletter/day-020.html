01 — 📌 本日導讀

當「事件」是資料本身出事

今天換一種事件——出事的不是端點，而是資料：敏感檔案被帶出組織、離職員工大量下載、機密郵件被人讀過。這類調查要的不是 EDR 遙測，而是合規等級的證據：誰、在何時碰了哪份資料，而且要禁得起法務檢視。Microsoft Purview 給你四件武器——DLP 警示、內部風險管理、eDiscovery、Audit——再加上 Security Copilot 內嵌體驗把速度拉起來。D2 占 35–40%，考題長相固定：給一個資料外洩情境，問「下一步該用哪個工具」。工具選錯，證據就沒了。

Purview 四件武器：先認位置

SC-200 不考你怎麼設計 DLP 政策（那是 SC-400 的事），考的是拿到訊號後去哪個工具找答案：

Purview 工具解決什麼問題SC-200 考點

DLP 警示怎麼調查？在 Purview 的 DLP 警示頁要回答四件事：比對到哪條規則與哪類敏感資訊、發生在哪個位置（Exchange、SharePoint、OneDrive、Teams、端點或雲端應用程式）、是誰、系統採取什麼動作（封鎖、僅稽核，或使用者填商業理由後覆寫）。有這四項，才判斷得出是意外、危險習慣，還是需要升級的入侵。而在 Defender XDR 這邊，DLP 警示會與其他訊號一起進入事件佇列：DLP 說某人外寄客戶名單、MDE 說他插了 USB、Entra 說他從陌生 IP 登入，三則警示關聯成同一起事件，故事才完整——這就是整合的價值。

04 — 🔍 核心概念

Audit：沒開就什麼都沒有

Purview Audit 是統一稽核記錄，橫跨 Exchange、SharePoint、OneDrive、Teams、Entra ID 等工作負載。Audit Standard 預設啟用，保留 180 天，可從 Purview 入口、PowerShell（Search-UnifiedAuditLog）或 API 查詢並匯出 CSV。Audit Premium（需 Microsoft 365 E5、E5 合規性或附加元件）多三件事：核心服務預設一年保留、可建立自訂保留政策、更深的智慧型洞察與更高的 API 頻寬。

保留期的數字要背：Standard 180 天；Premium 對 Exchange、SharePoint、OneDrive、Entra ID 預設一年，該預設政策不可改但可用自訂政策覆寫；自訂政策最多 50 條，依使用者、記錄類型或活動設定 7 天到 10 年（10 年需額外授權）。最容易出題的是：保留期在記錄產生的當下就決定，事後調高只對新資料生效，救不回已過期的記錄。

Premium 最具代表性的是郵件存取事件（MailItemsAccessed）——它回答的不是「檔案有沒有被下載」，而是「那封信到底有沒有被讀過」。存取類型分兩種：Bind 是個別郵件被開啟，Sync 是信箱被同步到用戶端（等同整批取走）。兩個細節也常入題：同一信箱每天超過 1,000 筆事件後會節流暫停記錄，重複項目自動過濾。分析可在入口網站篩選，或匯出 CSV（單次上限 50,000 筆）把 JSON 屬性展開成 IP 位址、存取類型等欄位再看。

// 若已用 Office 365 資料連接器把統一稽核記錄送進 Sentinel：
OfficeActivity
| where TimeGenerated > ago(30d)
| where Operation == "MailItemsAccessed"
| where UserId =~ "leaver@contoso.com"
| summarize Events = count(), IPs = make_set(ClientIP) by bin(TimeGenerated, 1d)
| sort by TimeGenerated desc
稽核記錄不只能在 Purview 查。用 Office 365 資料連接器擷取到 Sentinel 後，它落在 OfficeActivity 表，可跟登入、端點事件跨表關聯——這是 SC-200 特有的角度。
🎯 考點聚焦：稽核題的三個陷阱

陷阱一「以為全域管理員什麼都能查」：存取稽核記錄要另外指派 Purview 角色——Audit Reader 可搜尋與匯出，Audit Manager 另可管理稽核設定。陷阱二「用 Standard 查郵件是否被讀取」：Standard 給的是一般可見度（登入、檔案異動、分享），單封郵件是否被存取得靠 Premium。陷阱三「事後補保留政策」：事件發生在 200 天前而環境只有 Standard，正解是「已超出 180 天保留期，無法取得」，不是「延長保留期後重查」。所以調查的第一個好習慣是先確認稽核有沒有開——沒開，就沒有軌跡可追。

05 — 👤 核心概念

內部風險管理：把訊號串成模式

DLP 看的是單一動作，內部風險管理（insider risk management）看的是一個人的行為模式：下週離職、下載量是平時十倍、還把檔案改副檔名再上傳個人雲端硬碟——單看都不夠格報警，串起來就是智慧財產竊取，價值全在關聯。

運作鏈條是：訊號與指標（indicators）→ 政策偵測 → 警示分診 → 案件（case）調查 → 處置。政策從範本選起，常見的有離職員工資料竊取、資料外洩（含高優先權使用者、不滿員工的變體）、安全性政策違規、健康紀錄濫用、風險瀏覽器使用；再設定隱私選項、指標與評估時間範圍。三個前置條件必須先到位，否則一則警示都不會產生：稽核必須已啟用（指標來自稽核記錄）、指標要先在全域設定打開、離職範本要靠 HR 連接器匯入離職日等人資事件。

隱私是設計的一部分：內部風險管理預設把使用者名稱匿名化顯示，避免分析師在確認風險前就有預設立場；要看真實身分需具備調查者層級角色。案件調查完的處置有三條路：解決案件、送出使用者通知（教育為主），或升級以進行調查——這一步把案件交給 eDiscovery，接續正式的證據保全流程。
06 — ⚖️ 核心概念

eDiscovery：讓證據站得住腳

eDiscovery 是 Purview 裡「尋找、保全、匯出」內容的工具，用在內部調查、法律與法規要求與資安事件證據調閱。它跟內容搜尋（Content Search）差在哪？內容搜尋快，但缺少稽核軌跡與存取控制；eDiscovery 的每次搜尋都必須發生在「案件（case）」裡，案件是可稽核的工作區，搜尋、存取、匯出全部留下紀錄——這就是法律可辯護性（legally defensible）的來源。存取採案件成員制：有角色但沒被加入案件也看不到內容。角色分兩級：eDiscovery Manager 管理自己的案件、搜尋與匯出；eDiscovery Administrator 另可管理角色指派與存取所有案件。

比較面eDiscovery Standard（標準）eDiscovery Premium（進階）

搜尋流程要背順序：定義條件（關鍵字＋日期、寄件者、內容類型）→ 選定資料來源（使用者、群組、網站或整個租用戶）→ 建立查詢邏輯（條件建構器、KQL，或用 Copilot 轉自然語言）→ 驗證（看命中統計或抽樣確認相關性）→ 調整後重跑。最佳實務是先小後大：一開始就開到全租用戶，只會換來審閱不完的雜訊。確認後才匯出：選擇索引項目、部分索引項目或兩者，設定工作負載選項（版本歷程、對話串訊息、雲端附件）與輸出格式後下載封裝。封裝含資訊清單、記錄與雜湊值與有時效的下載連結——這就是保管鏈（chain of custody），證明資料從擷取到交付沒被竄改。

💼 實戰情境：離職工程師帶走設計圖

週一上午，Purview 送來一則 DLP 警示：某位工程師把標了「機密」的 CAD 檔上傳到個人雲端硬碟，政策動作是封鎖，但他填商業理由覆寫。第一步：看警示細節。比對到專有資料規則、位置是端點、動作是使用者覆寫——不是誤判；在 Defender XDR 篩出同類別警示，發現他當天還有一則 USB 警示，兩者已關聯成同一事件。第二步：拉稽核記錄。搜尋近 30 天活動，發現他上週從 SharePoint 專案庫下載 340 個檔案、多筆非上班時段存取；再用郵件存取事件確認他讀過主管那封含併購資訊的信，存取類型是 Bind。第三步：轉內部風險案件。HR 連接器顯示他兩週後離職，離職員工資料竊取政策早已對他評分；把證據併入案件，模式成立：離職＋大量下載＋外傳。第四步：eDiscovery 保全。案件升級以進行調查，建立 eDiscovery 案件，對他的信箱與 OneDrive 套用保留——從這一刻起，即使他刪除郵件、清空資源回收桶，內容仍在；接著搜尋、抽樣驗證，最後匯出帶雜湊的封裝交給法務。四個工具環環相扣，缺一環證據就斷。

07 — 🤖 核心概念

Copilot 內嵌調查與引導式回應

2026 新考點 上面那條調查鏈很完整，但很費時。Security Copilot 的內嵌體驗就是壓縮時間的方式：它直接長在 Defender XDR、Purview、Entra 的畫面裡，不必切換工具；需要跨產品深挖時再轉到獨立體驗。前提有兩個：外掛必須已啟用，而且使用者本人要具備存取底層產品與資料的權限——Copilot 不會替任何人越權。XDR 裡的能力清單常考「哪個能力對應哪種需求」：

  • 事件摘要：開啟事件頁時自動產生，把攻擊起點、時間軸、涉及資產、入侵指標甚至威脅執行者名稱組成敘事；單一事件最多摘要 100 則警示。
  • 引導式回應（guided response）：依事件脈絡並參考過往調查產出建議動作，分四類——分診（分類為資訊、真陽性或誤判）、控制、調查（下一步蒐集什麼證據）、修復（針對實體的動作），每張卡片會說明「為什麼建議這麼做」。
  • 指令碼分析：從警示時間軸的指令碼項目進入，支援 PowerShell、Batch、Bash，會去混淆、逐行解釋並標出 ATT&CK 技術。
  • 檔案分析與裝置摘要：前者評估檔案行為與風險（嵌入字串、API 呼叫、憑證），後者看裝置的弱點軟體與暴露程度。
  • 自然語言轉 KQL：在進階搜捕用一句話產生查詢，可直接執行或插入編輯器修改。
  • 事件報告：一鍵產出完整紀錄，含關鍵時間戳記、參與的分析師、分類結果與已執行的調查修復動作。
🎯 考點聚焦：摘要、報告、引導式回應別搞混

三個名詞常互當干擾項。事件摘要是「快速看懂發生什麼事」，打開事件時自動生成；事件報告是「留下可稽核的完整紀錄」，涵蓋整個事件生命週期與人為動作，對象是交班與稽核；引導式回應則是「接下來該做什麼」的建議清單。另一個高頻陷阱是拿它跟自動化比：題目若說「不需人工介入，對符合條件的事件固定執行相同動作」，答案是 Sentinel 的自動化規則或劇本——引導式回應只是建議，動作仍由分析師按下。最後記得 Purview 端也有內嵌 Copilot，可摘要 DLP 與內部風險警示、協助產生 eDiscovery 搜尋查詢；但要用 Purview 外掛，必須先開啟存取 Microsoft 365 服務資料。

08 — 🧩 考綱補洞

影片沒講到的角落

  • DLP 警示流進 XDR 的意義：影片只教你用類別篩選，但考題會問「為什麼要在 XDR 看 DLP 警示」——因為要跟身分、端點訊號放進同一起事件，才看得出是誤操作還是入侵者在竊取資料。
  • 調適性保護（Adaptive Protection）：把內部風險算出的風險層級回饋給 DLP，讓高風險使用者自動套用更嚴格管控——影片未涵蓋的整合考點。
  • 其他關鍵稽核事件：除了郵件存取，帳號調查常用的還有登入、檔案下載與分享、信箱權限變更；擷取到 Sentinel 的 OfficeActivity 表做跨來源關聯是 SC-200 的招牌動作。
  • eDiscovery 保留的實際效果：套用保留後，使用者即使刪除郵件，內容仍保存在可復原項目中。「先保全再搜尋」是核心紀律，證據才不會在調查期間蒸發。
  • Defender security store 的 agents：2026 新考點 釣魚分診、威脅情資簡報、威脅搜捕等 agent 需已佈建 SCU 容量才能部署，細節見 Day 11。

QUESTION 1 · D2-0041
You are a security operations analyst investigating a possible data breach. Legal asks you to confirm whether a departing employee actually opened a specific confidential email message in Exchange Online, not merely whether the mailbox was synchronized to a client. Your tenant is licensed for Microsoft 365 E5. Which Microsoft Purview Audit capability should you use?
（你是安全性作業分析師，正在調查一起可能的資料外洩。法務要求你確認某位離職員工是否真的開啟過 Exchange Online 中一封特定的機密郵件，而不只是信箱曾被同步到用戶端。租用戶具備 Microsoft 365 E5 授權。你應該使用哪一項 Microsoft Purview Audit 能力？）
A. Search Audit (Standard) for the FileAccessed activity in the audit log
在 Audit（Standard）中搜尋稽核記錄的 FileAccessed 活動
B. Search the MailItemsAccessed activity available with Audit (Premium) and review the access type
搜尋 Audit（Premium）提供的 MailItemsAccessed 活動，並檢視其存取類型
C. Create an Audit (Premium) custom retention policy scoped to the user's mailbox
建立一條範圍限定為該使用者信箱的 Audit（Premium）自訂保留原則
D. Run a Microsoft Purview eDiscovery (Standard) content search across the mailbox
對該信箱執行 Microsoft Purview eDiscovery（Standard）內容搜尋
看正解與解析
正解：B

MailItemsAccessed 是 Audit（Premium）的關鍵郵件存取事件，專門回答「這封信到底有沒有被讀過」。事件中的存取類型（AccessType）分為 **Bind**（個別郵件被開啟）與 **Sync**（信箱整批同步到用戶端），本題要區分「真的開啟」與「只是同步」，正是看這個欄位。實務上還要留意節流：同一信箱每天事件數超過門檻後會暫停記錄，重複事件也會被自動彙總。

  • A：FileAccessed 記錄的是 SharePoint／OneDrive 的檔案存取，不是信箱中的個別郵件；而且判斷郵件是否被讀取的 MailItemsAccessed 屬於 Premium 能力，Standard 取不到。
  • C：自訂保留原則只決定稽核記錄要保存多久，不會產生任何新的活動資料，也回答不了「信有沒有被讀過」；而且保留期是在記錄產生當下決定，事後建立原則對舊資料無效。
  • D：eDiscovery 內容搜尋能找出信箱裡「有哪些郵件」並加以保全與匯出，但它呈現的是內容本身，不是誰在什麼時間開啟過該郵件的存取行為紀錄。

QUESTION 2 · D2-0042
Your organization uses Microsoft Purview Audit (Standard) only. During an internal investigation you are asked to retrieve sign-in and file activity for an event that occurred 220 days ago. What should you report to the investigation lead?
（貴組織只使用 Microsoft Purview Audit（Standard）。在一次內部調查中，你被要求取得 220 天前某起事件的登入與檔案活動紀錄。你應該向調查負責人回報什麼？）
A. The activity is outside the 180-day retention period of Audit (Standard), so the audit records are no longer available
該活動已超出 Audit（Standard）的 180 天保留期，稽核記錄已無法取得
B. You can extend the Audit (Standard) retention period to one year and then rerun the search to recover the records
可以把 Audit（Standard）的保留期延長為一年，再重新搜尋即可取回紀錄
C. You can export the audit log to CSV, which bypasses the retention limit for older records
可以把稽核記錄匯出成 CSV，藉此略過舊紀錄的保留期限制
D. You can assign the Audit Manager role to gain access to records older than the retention period
可以指派 Audit Manager 角色，以取得超過保留期的紀錄
看正解與解析
正解：A

Audit（Standard）預設啟用，稽核記錄保留 **180 天**；220 天前的活動早已超出保留期，記錄不再存在，任何搜尋、匯出或權限調整都救不回來。這也是「調查第一步先確認稽核有沒有開、保留期夠不夠」的理由。若組織需要更長的軌跡，必須事先升級到 Audit（Premium）並建立自訂保留原則。

  • B：延長保留期屬於 Audit（Premium）的自訂保留原則能力，而且保留期是在記錄產生的當下就決定的——變更只對之後產生的新資料生效，無法回溯救回已過期的記錄。
  • C：匯出 CSV 只是把「還留存在系統中」的搜尋結果帶出來（且單次有筆數上限），完全不會改變保留期，已被清除的紀錄無從匯出。
  • D：Audit Manager 決定的是誰可以搜尋、匯出與管理稽核設定，屬於權限層面；權限再大也讀不到已經因保留期到期而不存在的資料。

QUESTION 3 · D2-0043
A Microsoft Purview data loss prevention (DLP) policy blocks a user from uploading a document that contains proprietary data, and the user completes a business justification to override the block. As the analyst on duty, you want to see this DLP alert correlated with the same user's endpoint and identity signals in a single investigation view. What should you do?
（一條 Microsoft Purview 資料外洩防護（DLP）原則封鎖了某使用者上傳含專有資料的文件，該使用者填寫商業理由後覆寫了封鎖動作。身為值班分析師，你想在單一調查畫面中，把這則 DLP 警示與同一使用者的端點及身分訊號關聯在一起。你應該怎麼做？）
A. Open an eDiscovery (Premium) case and add the user as a custodian
開立一個 eDiscovery（Premium）案件並把該使用者加為保管人
B. Create a Microsoft Sentinel automation rule that tags DLP alerts
建立一條為 DLP 警示加標籤的 Microsoft Sentinel 自動化規則
C. Turn on Audit (Premium) custom retention for the user's mailbox
為該使用者的信箱開啟 Audit（Premium）自訂保留
D. Review the incident in Microsoft Defender XDR, filtering the alert queue by the data loss prevention alert category
在 Microsoft Defender XDR 檢視該事件，並以資料外洩防護（data loss prevention）警示類別篩選警示佇列
看正解與解析
正解：D

Purview DLP 警示會流進 Microsoft Defender XDR 的警示佇列，並與其他來源的警示關聯成同一起事件——這正是整合的價值：DLP 說使用者外寄資料、Defender for Endpoint 說他接了 USB、Entra 說他從陌生 IP 登入，合起來才看得出是一次外洩而非單一誤操作。實務做法是在警示佇列以「資料外洩防護」類別篩選，快速從整條佇列切到資料相關的子集；Defender for Cloud Apps 的警示同樣已整併進 XDR。另外，使用者「填商業理由覆寫」本身就是調查時的重要訊號。

  • A：eDiscovery 案件用於證據的保全、搜尋與匯出，是調查後期的動作；它不會把 DLP、端點與身分警示關聯成一起事件，也不提供分診用的調查畫面。
  • B：自動化規則是 Sentinel 事件層的自動處理（改狀態、指派、加標籤、跑劇本），只是加工既有事件，本身不負責跨產品的警示關聯，也不是「看到關聯後的調查視圖」的手段。
  • C：自訂保留只影響稽核記錄保存多久，對警示關聯與分診沒有幫助；它解決的是「日後還查不查得到軌跡」，不是「現在如何一起看」。

QUESTION 4 · D2-0044
An insider risk management case is escalated for investigation. Legal requires that the suspect's mailbox and OneDrive content be preserved so it cannot be deleted, that every search and export be auditable, and that hold notifications be sent to and tracked for multiple custodians. Which approach meets all of the requirements?
（一件內部風險管理案件被升級以進行調查。法務要求：必須保全嫌疑人的信箱與 OneDrive 內容使其無法被刪除、每一次搜尋與匯出都要可稽核，並且要對多位保管人寄送保留通知並追蹤回覆。哪一種做法能滿足全部要求？）
A. Run a content search across the tenant and export the results to PST files
對整個租用戶執行內容搜尋，並把結果匯出成 PST 檔案
B. Create an eDiscovery (Standard) case, run searches in the case, and export the results
建立 eDiscovery（Standard）案件，在案件中執行搜尋並匯出結果
C. Create an eDiscovery (Premium) case with custodian-based holds and legal hold notifications
建立 eDiscovery（Premium）案件，使用以保管人為中心的保留與法務保留通知
D. Configure an Audit (Premium) custom retention policy for the users involved
為相關使用者設定 Audit（Premium）自訂保留原則
看正解與解析
正解：C

三項要求要一起看：保全內容、可稽核、以及**保管人保留通知的寄送與追蹤**。前兩項 eDiscovery（Standard）就做得到——案件即可稽核的工作區、案件層級保留可凍結指定位置的內容；但「以保管人為中心的保留」與「法務保留通知（legal hold notification）」的通知工作流程屬於 **eDiscovery（Premium）**，另外 Premium 還提供內建審閱集。題目出現「多位保管人」「通知並追蹤」這類字眼，就是在指向 Premium。

  • A：內容搜尋速度快，但缺少案件層級的存取控制與稽核軌跡，而且它不會保全任何東西——搜尋期間使用者仍可刪除內容，證據會在調查中蒸發。
  • B：Standard 能建立案件、搜尋、套用案件層級保留並匯出，滿足前兩項要求，但沒有保管人管理與法務保留通知的工作流程，無法達成「寄送並追蹤通知」。
  • D：自訂保留原則保存的是**稽核記錄**（誰做了什麼的活動軌跡），不是郵件與檔案內容本身；它無法阻止使用者刪除郵件，也不提供搜尋、審閱或匯出證據的能力。

QUESTION 5 · D2-0045
After closing a multi-stage incident in Microsoft Defender XDR, your SOC lead asks for a single auditable record of the whole incident lifecycle, including key timestamps, which analysts were involved, how the incident was classified, and the investigation and remediation actions that were taken. Which embedded Microsoft Security Copilot capability should you use?
（在 Microsoft Defender XDR 中結案一起多階段事件後，SOC 主管要求提供一份涵蓋整個事件生命週期的可稽核紀錄，包含關鍵時間戳記、參與的分析師、事件如何被分類，以及已執行的調查與修復動作。你應該使用哪一項內嵌的 Microsoft Security Copilot 能力？）
A. The incident summary that Copilot generates automatically on the incident page
Copilot 在事件頁自動產生的事件摘要（incident summary）
B. Guided response recommendations for the incident
針對該事件的引導式回應（guided response）建議
C. Generate an incident report with Copilot
用 Copilot 產生事件報告（incident report）
D. The script analysis capability in the alert timeline
警示時間軸中的指令碼分析（script analysis）能力
看正解與解析
正解：C

**事件報告（incident report）**是內嵌 Copilot 一鍵產出的完整、可稽核紀錄，整合事件管理的關鍵時間戳記、參與的分析師、分類結果、已執行的調查與修復動作，以及後續建議，適合交班、主管檢視與稽核留存。與它最容易混淆的是事件摘要：摘要是「快速看懂發生什麼事」，報告是「留下完整紀錄」——這組對比是高頻考點。

  • A：事件摘要會在你開啟事件頁時自動產生，把攻擊起點、時間軸、涉及資產與入侵指標組成一段敘事，用途是讓分析師快速進入狀況；它不涵蓋分析師的人為動作與分類決定，稽核價值不足。
  • B：引導式回應提供的是分診、控制、調查、修復四類的**建議動作**，是事件處理當下的行動指引，而且動作仍由分析師執行；它不是事後的紀錄文件。
  • D：指令碼分析用於從警示時間軸還原混淆的 PowerShell、Batch 或 Bash 指令碼並解釋其行為，範圍只在單一指令碼，與整起事件生命週期的紀錄無關。
