01 — 📌 本日導讀

當「事件」是資料本身出事

今天換一種事件——出事的不是端點，而是資料：敏感檔案被帶出組織、離職員工大量下載、機密郵件被人讀過。這類調查要的不是 EDR 遙測，而是合規等級的證據：誰、在何時碰了哪份資料，而且要禁得起法務檢視。Microsoft Purview 給你四件武器——DLP 警示、內部風險管理、eDiscovery、Audit——再加上 Security Copilot 內嵌體驗把速度拉起來。D2 占 35–40%，考題長相固定：給一個資料外洩情境，問「下一步該用哪個工具」。工具選錯，證據就沒了。

Purview 四件武器：先認位置

SC-200 不考你怎麼設計 DLP 政策（那是 SC-400 的事），考的是拿到訊號後去哪個工具找答案：

Purview 工具解決什麼問題SC-200 考點

DLP 警示怎麼調查？在 Purview 的 DLP 警示頁要回答四件事：比對到哪條規則與哪類敏感資訊、發生在哪個位置（Exchange、SharePoint、OneDrive、Teams、端點或雲端應用程式）、是誰、系統採取什麼動作（封鎖、僅稽核，或使用者填商業理由後覆寫）。有這四項，才判斷得出是意外、危險習慣，還是需要升級的入侵。而在 Defender XDR 這邊，DLP 警示會與其他訊號一起進入事件佇列：DLP 說某人外寄客戶名單、MDE 說他插了 USB、Entra 說他從陌生 IP 登入，三則警示關聯成同一起事件，故事才完整——這就是整合的價值。

04 — 🔍 核心概念

Audit：沒開就什麼都沒有

Purview Audit 是統一稽核記錄，橫跨 Exchange、SharePoint、OneDrive、Teams、Entra ID 等工作負載。Audit Standard 預設啟用，保留 180 天，可從 Purview 入口、PowerShell（Search-UnifiedAuditLog）或 API 查詢並匯出 CSV。Audit Premium（需 Microsoft 365 E5、E5 合規性或附加元件）多三件事：核心服務預設一年保留、可建立自訂保留政策、更深的智慧型洞察與更高的 API 頻寬。

保留期的數字要背：Standard 180 天；Premium 對 Exchange、SharePoint、OneDrive、Entra ID 預設一年，該預設政策不可改但可用自訂政策覆寫；自訂政策最多 50 條，依使用者、記錄類型或活動設定 7 天到 10 年（10 年需額外授權）。最容易出題的是：保留期在記錄產生的當下就決定，事後調高只對新資料生效，救不回已過期的記錄。

Premium 最具代表性的是郵件存取事件（MailItemsAccessed）——它回答的不是「檔案有沒有被下載」，而是「那封信到底有沒有被讀過」。存取類型分兩種：Bind 是個別郵件被開啟，Sync 是信箱被同步到用戶端（等同整批取走）。兩個細節也常入題：同一信箱每天超過 1,000 筆事件後會節流暫停記錄，重複項目自動過濾。分析可在入口網站篩選，或匯出 CSV（單次上限 50,000 筆）把 JSON 屬性展開成 IP 位址、存取類型等欄位再看。

// 若已用 Office 365 資料連接器把統一稽核記錄送進 Sentinel：
OfficeActivity
| where TimeGenerated > ago(30d)
| where Operation == "MailItemsAccessed"
| where UserId =~ "leaver@contoso.com"
| summarize Events = count(), IPs = make_set(ClientIP) by bin(TimeGenerated, 1d)
| sort by TimeGenerated desc
稽核記錄不只能在 Purview 查。用 Office 365 資料連接器擷取到 Sentinel 後，它落在 OfficeActivity 表，可跟登入、端點事件跨表關聯——這是 SC-200 特有的角度。
🎯 考點聚焦：稽核題的三個陷阱

陷阱一「以為全域管理員什麼都能查」：存取稽核記錄要另外指派 Purview 角色——Audit Reader 可搜尋與匯出，Audit Manager 另可管理稽核設定。陷阱二「用 Standard 查郵件是否被讀取」：Standard 給的是一般可見度（登入、檔案異動、分享），單封郵件是否被存取得靠 Premium。陷阱三「事後補保留政策」：事件發生在 200 天前而環境只有 Standard，正解是「已超出 180 天保留期，無法取得」，不是「延長保留期後重查」。所以調查的第一個好習慣是先確認稽核有沒有開——沒開，就沒有軌跡可追。

05 — 👤 核心概念

內部風險管理：把訊號串成模式

DLP 看的是單一動作，內部風險管理（insider risk management）看的是一個人的行為模式：下週離職、下載量是平時十倍、還把檔案改副檔名再上傳個人雲端硬碟——單看都不夠格報警，串起來就是智慧財產竊取，價值全在關聯。

運作鏈條是：訊號與指標（indicators）→ 政策偵測 → 警示分診 → 案件（case）調查 → 處置。政策從範本選起，常見的有離職員工資料竊取、資料外洩（含高優先權使用者、不滿員工的變體）、安全性政策違規、健康紀錄濫用、風險瀏覽器使用；再設定隱私選項、指標與評估時間範圍。三個前置條件必須先到位，否則一則警示都不會產生：稽核必須已啟用（指標來自稽核記錄）、指標要先在全域設定打開、離職範本要靠 HR 連接器匯入離職日等人資事件。

隱私是設計的一部分：內部風險管理預設把使用者名稱匿名化顯示，避免分析師在確認風險前就有預設立場；要看真實身分需具備調查者層級角色。案件調查完的處置有三條路：解決案件、送出使用者通知（教育為主），或升級以進行調查——這一步把案件交給 eDiscovery，接續正式的證據保全流程。
06 — ⚖️ 核心概念

eDiscovery：讓證據站得住腳

eDiscovery 是 Purview 裡「尋找、保全、匯出」內容的工具，用在內部調查、法律與法規要求與資安事件證據調閱。它跟內容搜尋（Content Search）差在哪？內容搜尋快，但缺少稽核軌跡與存取控制；eDiscovery 的每次搜尋都必須發生在「案件（case）」裡，案件是可稽核的工作區，搜尋、存取、匯出全部留下紀錄——這就是法律可辯護性（legally defensible）的來源。存取採案件成員制：有角色但沒被加入案件也看不到內容。角色分兩級：eDiscovery Manager 管理自己的案件、搜尋與匯出；eDiscovery Administrator 另可管理角色指派與存取所有案件。

比較面eDiscovery Standard（標準）eDiscovery Premium（進階）

搜尋流程要背順序：定義條件（關鍵字＋日期、寄件者、內容類型）→ 選定資料來源（使用者、群組、網站或整個租用戶）→ 建立查詢邏輯（條件建構器、KQL，或用 Copilot 轉自然語言）→ 驗證（看命中統計或抽樣確認相關性）→ 調整後重跑。最佳實務是先小後大：一開始就開到全租用戶，只會換來審閱不完的雜訊。確認後才匯出：選擇索引項目、部分索引項目或兩者，設定工作負載選項（版本歷程、對話串訊息、雲端附件）與輸出格式後下載封裝。封裝含資訊清單、記錄與雜湊值與有時效的下載連結——這就是保管鏈（chain of custody），證明資料從擷取到交付沒被竄改。

💼 實戰情境：離職工程師帶走設計圖

週一上午，Purview 送來一則 DLP 警示：某位工程師把標了「機密」的 CAD 檔上傳到個人雲端硬碟，政策動作是封鎖，但他填商業理由覆寫。第一步：看警示細節。比對到專有資料規則、位置是端點、動作是使用者覆寫——不是誤判；在 Defender XDR 篩出同類別警示，發現他當天還有一則 USB 警示，兩者已關聯成同一事件。第二步：拉稽核記錄。搜尋近 30 天活動，發現他上週從 SharePoint 專案庫下載 340 個檔案、多筆非上班時段存取；再用郵件存取事件確認他讀過主管那封含併購資訊的信，存取類型是 Bind。第三步：轉內部風險案件。HR 連接器顯示他兩週後離職，離職員工資料竊取政策早已對他評分；把證據併入案件，模式成立：離職＋大量下載＋外傳。第四步：eDiscovery 保全。案件升級以進行調查，建立 eDiscovery 案件，對他的信箱與 OneDrive 套用保留——從這一刻起，即使他刪除郵件、清空資源回收桶，內容仍在；接著搜尋、抽樣驗證，最後匯出帶雜湊的封裝交給法務。四個工具環環相扣，缺一環證據就斷。

07 — 🤖 核心概念

Copilot 內嵌調查與引導式回應

2026 新考點 上面那條調查鏈很完整，但很費時。Security Copilot 的內嵌體驗就是壓縮時間的方式：它直接長在 Defender XDR、Purview、Entra 的畫面裡，不必切換工具；需要跨產品深挖時再轉到獨立體驗。前提有兩個：外掛必須已啟用，而且使用者本人要具備存取底層產品與資料的權限——Copilot 不會替任何人越權。XDR 裡的能力清單常考「哪個能力對應哪種需求」：

  • 事件摘要：開啟事件頁時自動產生，把攻擊起點、時間軸、涉及資產、入侵指標甚至威脅執行者名稱組成敘事；單一事件最多摘要 100 則警示。
  • 引導式回應（guided response）：依事件脈絡並參考過往調查產出建議動作，分四類——分診（分類為資訊、真陽性或誤判）、控制、調查（下一步蒐集什麼證據）、修復（針對實體的動作），每張卡片會說明「為什麼建議這麼做」。
  • 指令碼分析：從警示時間軸的指令碼項目進入，支援 PowerShell、Batch、Bash，會去混淆、逐行解釋並標出 ATT&CK 技術。
  • 檔案分析與裝置摘要：前者評估檔案行為與風險（嵌入字串、API 呼叫、憑證），後者看裝置的弱點軟體與暴露程度。
  • 自然語言轉 KQL：在進階搜捕用一句話產生查詢，可直接執行或插入編輯器修改。
  • 事件報告：一鍵產出完整紀錄，含關鍵時間戳記、參與的分析師、分類結果與已執行的調查修復動作。
🎯 考點聚焦：摘要、報告、引導式回應別搞混

三個名詞常互當干擾項。事件摘要是「快速看懂發生什麼事」，打開事件時自動生成；事件報告是「留下可稽核的完整紀錄」，涵蓋整個事件生命週期與人為動作，對象是交班與稽核；引導式回應則是「接下來該做什麼」的建議清單。另一個高頻陷阱是拿它跟自動化比：題目若說「不需人工介入，對符合條件的事件固定執行相同動作」，答案是 Sentinel 的自動化規則或劇本——引導式回應只是建議，動作仍由分析師按下。最後記得 Purview 端也有內嵌 Copilot，可摘要 DLP 與內部風險警示、協助產生 eDiscovery 搜尋查詢；但要用 Purview 外掛，必須先開啟存取 Microsoft 365 服務資料。

08 — 🧩 考綱補洞

影片沒講到的角落

  • DLP 警示流進 XDR 的意義：影片只教你用類別篩選，但考題會問「為什麼要在 XDR 看 DLP 警示」——因為要跟身分、端點訊號放進同一起事件，才看得出是誤操作還是入侵者在竊取資料。
  • 調適性保護（Adaptive Protection）：把內部風險算出的風險層級回饋給 DLP，讓高風險使用者自動套用更嚴格管控——影片未涵蓋的整合考點。
  • 其他關鍵稽核事件：除了郵件存取，帳號調查常用的還有登入、檔案下載與分享、信箱權限變更；擷取到 Sentinel 的 OfficeActivity 表做跨來源關聯是 SC-200 的招牌動作。
  • eDiscovery 保留的實際效果：套用保留後，使用者即使刪除郵件，內容仍保存在可復原項目中。「先保全再搜尋」是核心紀律，證據才不會在調查期間蒸發。
  • Defender security store 的 agents：2026 新考點 釣魚分診、威脅情資簡報、威脅搜捕等 agent 需已佈建 SCU 容量才能部署，細節見 Day 11。
