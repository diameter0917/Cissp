01 — 📌 本日導讀

本日導讀：從「看懂事件」到「按下按鈕」

昨天我們把事件分診（triage）做完，判斷出「這台裝置真的中了」。今天就要動手：在 Microsoft Defender for Endpoint（MDE，微軟端點偵測與回應平台）上對裝置執行回應動作。D2「回應安全性事件」占考試 35–40%，裝置回應最會出情境題——題幹給你一個正在延燒的攻擊，四個選項全是真實存在的動作，要你選「這一步該做哪一個」。光背功能名稱沒用，你得同時掌握三件事：這個動作改變了裝置的什麼、可不可逆、該放在回應流程的哪一格。今天沿著這三個軸線把工具箱拆完，最後用勒索軟體的完整 walkthrough 把順序串起來。

學習目標（對應官方考綱 D2「回應安全性事件」條目）：
  • ☐ 在裝置上執行回應動作（perform actions on a device），包含隔離、限制應用程式執行、防毒掃描與收集調查套件
  • ☐ 使用即時回應（Live Response）對裝置進行深入取證與修復
  • ☐ 執行證據與實體調查（perform evidence and entity investigation），包含檔案的 stop and quarantine
  • ☐ 以自動調查與修復（AIR）調查並修復威脅，管理 Action center 的待核准動作與復原（undo）
  • ☐ 以指標（indicators）封鎖檔案雜湊、IP 與 URL，並確保回應動作留下稽核軌跡

03 — 🧰 裝置回應動作全集

回應動作 × 效果 × 可逆性 × 適用時機

裝置回應動作分三類：遏制型（隔離、限制應用程式執行）、調查型（收集調查套件、Live Response）、清除型（防毒掃描、stop and quarantine、AIR 修復）。下表是本日最該背的東西：

回應動作實際效果可逆性適用時機
Isolate device（完全隔離）切斷所有網路連線，只保留與 Defender 雲端服務的通道，因此仍能繼續調查可逆：Release from isolation已確認遭入侵，要立刻阻斷橫向移動與外傳
Isolate device（選擇性隔離）只封鎖有限的一組應用程式對外連線，Outlook、Teams、Skype for Business 仍可運作可逆要遏制、又不能讓使用者完全失聯（較新版 Windows 用戶端限定）
Restrict app execution套用程式碼完整性原則，只允許 Microsoft 簽發憑證簽章的檔案執行；網路照通可逆：Remove app restriction疑有不明二進位檔在跑，但業務不能斷網（Windows 限定）
Run antivirus scan觸發 Defender 防毒快速或完整掃描並清除偵測到的項目無「取消」，但隔離區檔案可還原遏制後的清理階段、確認殘留
Collect investigation package打包鑑識產物成 ZIP：autoruns、處理程序、網路連線與 DNS／ARP 快取、排程工作、服務、prefetch、安全性事件記錄檔等唯讀，不改變裝置狀態取證、事後報告、交付第三方 IR 團隊
Stop and quarantine file依檔案雜湊停止執行中的處理程序並在租用戶範圍內隔離該檔（限可執行檔類型）可逆：Action center 還原檔案已確認惡意的檔案散布在多台裝置
Initiate automated investigation手動啟動 AIR 自動蒐證、判定並提出修復動作修復動作可在 Action center undo讓自動化先把影響範圍跑一輪
Initiate Live Response session開遠端命令列工作階段，做標準動作辦不到的手術式取證與修復視命令而定（remediate 可 undo）抓特定檔案、看登錄、跑自訂指令碼
Add indicator（block）建立持續性封鎖規則：檔案雜湊、IP、URL／網域、憑證，可限定裝置群組可逆：刪除或改為 Allow／Audit防止同一個 IoC 再次進入環境
Contain device針對未上線的探索到裝置：命令已上線裝置拒絕與它通訊可逆沒有代理程式、下不了隔離的裝置遭入侵
💡 最容易混淆的三者：隔離切「網路」、限制應用程式執行切「執行權」、指標封鎖切「未來再出現的機會」。題目出現「使用者必須繼續工作、不能斷網」，隔離出局；出現「阻止它再度進來」，答案往指標走。
🎯 考點聚焦

完全隔離 vs 選擇性隔離。兩者都保留裝置與 Defender 服務的連線，差別在使用者還剩下什麼：完全隔離＝除了 Defender 通道什麼都不通；選擇性隔離＝只擋一組應用程式的網路存取，刻意留下 Outlook／Teams／Skype for Business，僅較新版 Windows 用戶端支援，macOS 與 Linux 只有完全隔離。題幹寫「必須能繼續透過 Teams 聯絡該員工」→ 選擇性隔離；寫「阻止所有對外通訊、防止資料外流」→ 完全隔離。陷阱選項是「請使用者拔網路線／關機」——會切斷 Defender 通道、毀掉揮發性證據，永遠不是最佳答案。

04 — 🩺 Live Response 實戰

即時回應：把命令列開到那台機器上

標準動作不夠用時——要看登錄機碼、抓一份可疑 DLL 回來分析、跑自訂蒐證腳本——就輪到即時回應（Live Response）。它等於在瀏覽器裡開遠端 shell，而且裝置在隔離狀態下依然可用。

啟用前置條件（考題最愛考「為什麼按鈕是灰的」）：進階功能頁必須開啟 Live Response；要對伺服器操作得另外開 Live Response for servers；要跑未簽章的自訂指令碼還要開 Live response unsigned script execution。裝置需為受支援的作業系統版本且已上線，使用者需具備對應 RBAC 權限。

工作階段限制：一台裝置同時只能有一個工作階段；每位使用者可同時開啟的數量與租用戶總量都有上限；閒置會自動逾時中斷。「兩位分析師同時對同一台機器下命令」的答案是不行，得等前一個結束。

命令做什麼權限層級
cd / dir切換與列出目錄內容，探索檔案系統基本（basic）
fileinfo顯示檔案中繼資料：雜湊、大小、簽章者、建立時間基本
findfile依檔名在裝置上搜尋檔案位置基本
processes列出執行中的處理程序（含 PID、命令列）基本
connections列出作用中的網路連線，找 C2 通訊基本
services / drivers列出服務與已載入的驅動程式基本
registry讀取登錄機碼與值基本
scheduledtasks / startupfolders / persistence檢視常見持續性（persistence）機制基本
getfile把裝置上的檔案取回供離線分析——取證主力命令基本
analyze對檔案或處理程序做深入分析並取得判定進階（unrestricted）
library管理 live response library：上傳／列出／刪除腳本與工具進階
putfile把 library 中的檔案放到裝置上進階
run執行 library 中的指令碼（自訂蒐證／修復腳本）進階
remediate移除或隔離惡意檔案、處理程序、排程工作等進階
undo復原本工作階段中做過的 remediate進階
& / fg / jobs / status把長時間命令丟到背景、切回前景、查看工作狀態基本
💡 記憶法：「唯讀的是 basic，會改變裝置或放東西進去的是 unrestricted」——特別記住 getfile 是把檔案「拿出來」，屬於基本命令；putfile、run、remediate、undo、library、analyze 才需要進階權限。
🎯 考點聚焦

「分析師連得上、也能列出處理程序，卻無法執行自訂指令碼」——為什麼？三層檢查：(1) 使用者只有基本命令權限，缺 unrestricted（進階命令）權限；(2) 進階功能的 Live response unsigned script execution 沒開，而腳本未簽章；(3) 腳本沒上傳到 library——run 只能執行 library 裡的檔案。若題目說「完全開不了工作階段」，那是 Live Response 主開關或伺服器開關沒開。
高頻對比：getfile vs collect investigation package。題幹說「把可疑執行檔送沙箱分析」→ getfile；說「保存整台機器的完整鑑識資料」→ 調查套件。

05 — 🤖 自動調查與修復（AIR）

AIR：讓機器先跑完第一輪

自動調查與修復（AIR）是 MDE 幫你配的「Tier 1 分析師」：警示觸發後自動檢查相關檔案、處理程序、服務、驅動程式、排程工作與網路連線，對每個實體給出「惡意／可疑／乾淨」判定，並產生對應的修復動作。

  • 觸發方式：多數由警示自動觸發；分析師也可在裝置頁手動按 Initiate automated investigation；在 Defender XDR 事件層級，調查可跨裝置擴展。
  • 調查狀態：Queued、Running、Pending approval、No threats found、Partially remediated、Remediated、Terminated、Failed——看到 Pending approval 就是有動作卡著等人核准。
  • 自動化層級綁在裝置群組上：full（自動修復，官方建議值）、三種 semi（不同範圍需核准）、no automated response（完全不跑，官方不建議）。要讓伺服器人工把關、工作站全自動，作法永遠是建立不同裝置群組各自設層級。
  • Action center：Pending（待核准）是你批准或駁回自動修復的地方；History（歷史紀錄）記錄所有已完成動作（自動與手動都算），並提供 undo——解除隔離、移除應用程式執行限制、從隔離區還原檔案、移除封鎖指標。
🎯 考點聚焦

「AIR 沒有修復任何東西」的四種標準原因：(1) 裝置所屬群組的自動化層級是 semi，動作停在 Action center 等核准 → 去核准或調成 full；(2) 層級是 no automated response，調查根本沒啟動；(3) 裝置沒落在你以為的群組（群組有順位，由上往下命中第一個就停）；(4) Defender 防毒未啟用，部分修復動作無法執行。
必考觀念：full 自動化不等於不可挽回——官方建議 full 正是因為所有動作都留在 Action center 且可以 undo。選項寫「為了安全起見關閉整個租用戶的自動化」，直接刪掉。

06 — 🚧 指標封鎖與擴散控制

封鎖 IoC：一次性清除 vs 持續性封鎖

回應的最後一哩是「別讓它再進來」。stop and quarantine file 是一次性清除（殺掉目前環境中的那個檔案），indicator 是持續性封鎖規則（未來這個雜湊／IP／URL 再出現就擋）。完整的回應兩個都做。

  • 檔案雜湊指標：動作可設 Allow／Audit／Warn／Block and remediate；前提是 Defender 防毒處於主動模式且開啟雲端保護。
  • IP／URL／網域指標：前提是裝置啟用網路保護（network protection），且進階功能開啟 custom network indicators——「建了封鎖指標卻沒生效」的標準答案。
  • 憑證指標：封鎖以某張簽章憑證簽署的所有檔案，對付整批同源工具。
  • 範圍與治理：指標可限定套用到特定裝置群組；租用戶有數量配額，過期 IoC 要定期清理。

按下 stop and quarantine 之前，先用一段進階搜捕（advanced hunting）確認擴散範圍：

let badHash = "3a1f…（換成事件中的 SHA256）";
DeviceFileEvents
| where Timestamp > ago(30d)
| where SHA256 == badHash
| summarize FirstSeen = min(Timestamp), LastSeen = max(Timestamp),
            Paths = make_set(FolderPath, 5) by DeviceName, FileName
| order by FirstSeen asc
逐行解說：let 把惡意檔案的 SHA256 存成變數，換 IoC 只改一行；DeviceFileEvents 記錄檔案建立、修改、複製等事件，是追檔案足跡的主表；where SHA256 == 比對雜湊（雜湊比檔名可靠，檔名可以隨便改）；summarize … by DeviceName 得出「哪幾台裝置出現過、各自最早何時出現」，order by FirstSeen asc 排最前面的那台很可能就是零號病人（patient zero）。有這份清單，你才知道要隔離幾台、指標要不要放到全租用戶範圍。
07 — 🧪 完整回應演練

勒索軟體疑似感染：從警示到收尾

🧪 實戰情境：財務部筆電出現勒索軟體行為警示

財務部筆電 FIN-LAP-014 出現「疑似勒索軟體行為」高嚴重性警示，處理程序 invoice_2026.exe 正在大量重新命名檔案並與未知外部 IP 通訊。你是值班分析師——

  1. 先遏制（14:22）：執行完全隔離並填寫理由，切斷加密擴散與對外的 C2／外傳通道，但不影響後續調查，因為 Defender 通道仍在。若必須保持與使用者聯絡，才改用選擇性隔離。
  2. 收集鑑識快照（14:25）：執行 collect investigation package，把處理程序、網路連線、排程工作、autoruns、事件記錄檔一次打包，之後從 Action center 下載存證。
  3. 手術式取證（14:30）：開 Live Response：processes 確認可疑處理程序仍在、connections 記下 C2 的 IP 與埠、fileinfo 取得檔案 SHA256、scheduledtasks 與 persistence 檢查後門，最後 getfile 把執行檔取回送沙箱。
  4. 評估擴散（14:40）：拿 SHA256 跑第 06 節那段 advanced hunting，發現另外兩台裝置前一天也出現同一檔案——納入事件、視情況隔離。
  5. 清除（14:50）：對該檔案執行 stop and quarantine file（涵蓋三台裝置），必要時用 remediate 清掉持續性項目，再跑完整防毒掃描確認乾淨。
  6. 封鎖未來（15:00）：為 SHA256 建立 Block and remediate 檔案指標、為 C2 的 IP 與 URL 建立網路指標（確認網路保護與 custom network indicators 已開）。
  7. 復原收尾（15:30 起）：確認乾淨後解除隔離，用 Action center 歷史紀錄當事件報告附件，把分類（classification）標為 True positive／Ransomware 結案。若某個被隔離的檔案其實是誤判，從 Action center undo 還原。
🎯 考點聚焦

「先隔離還是先取證？」是本單元最常見的排序題。正確答案幾乎永遠是先隔離，理由要背起來：MDE 的隔離保留裝置與 Defender 服務的連線，隔離後照樣能收集調查套件、開 Live Response、跑掃描，取證能力不受影響；晚一步遏制，攻擊者可能已橫向移動或把資料外傳完畢。所以「隔離→取證→清除→封鎖→解除」這個順序是安全的。
唯一反過來的情境，是題幹明說「不能中斷這台機器的網路服務」（生產線控制器、關鍵伺服器）——最佳解通常是 restrict app execution（擋執行不擋網路）搭配立即取證，或改用選擇性隔離。至於「請使用者關機」「拔網路線」，會失去揮發性證據又切斷管理通道，永遠是錯的。

08 — 🧩 考綱補洞

影片之外，考綱還要你會這些

  • Contain device 與 contain user：對探索到但未上線的裝置下不了隔離，改用 contain device——已上線裝置會拒絕與它通訊，等於用周邊裝置圍一道牆。身分側對應的是 contain user。
  • 自動攻擊中斷（automatic attack disruption）：Defender XDR 在高信心判定下會自動遏制進行中的攻擊（勒索軟體、AiTM 釣魚、資料外洩）——自動隔離裝置或停用帳戶，動作同樣列在 Action center 且可復原。考題關鍵字：「分析師介入前系統就已遏制」。
  • 回應動作的稽核：Action center 歷史紀錄是第一手稽核來源（誰、何時、對哪台、結果）；Live Response 每個工作階段都有完整命令記錄可匯出。考題問「如何證明某分析師何時隔離了裝置」→ Action center／稽核記錄，不是裝置時間軸。
  • 權限模型：隔離、限制執行、掃描需要「主動修復動作」類權限；Live Response 另分基本與進階兩級；核准 AIR 動作又是另一項權限，且可依裝置群組範圍指派——能看到裝置 ≠ 能對它動手。
  • Security Copilot 引導式回應 2026 新考點：事件頁的 guided response 直接建議下一步（隔離裝置、封鎖寄件者、停用帳戶）並可一鍵執行，也能把 AIR 調查結果摘要成人話。考題問「如何加速 Tier 1 的回應決策」。

QUESTION 1 · D2-0006
You are a security operations analyst. Malware is confirmed on the Windows 11 laptop of a remote employee. You must stop the laptop from reaching other network resources, but the service desk must still be able to contact the employee through Microsoft Teams and Outlook while you investigate. Which response action in Microsoft Defender for Endpoint should you use?
（你是安全性作業分析師。一名遠端員工的 Windows 11 筆電已確認感染惡意程式。你必須阻止這台筆電存取其他網路資源，但在調查期間服務台仍必須能透過 Microsoft Teams 與 Outlook 聯絡到該員工。你應該使用 Microsoft Defender for Endpoint 的哪一個回應動作？）
A. Isolate the device by using full isolation
以完全隔離（full isolation）隔離裝置
B. Isolate the device by using selective isolation
以選擇性隔離（selective isolation）隔離裝置
C. Restrict app execution on the device
對裝置套用限制應用程式執行（restrict app execution）
D. Contain the device from the neighbouring onboarded devices
由周邊已上線的裝置對它執行 contain device（圍堵裝置）
看正解與解析
正解：B

選擇性隔離只封鎖一組應用程式的對外網路存取，刻意保留 Outlook、Teams 與 Skype for Business，正好符合「要遏制、又不能讓使用者完全失聯」的需求（僅較新版 Windows 用戶端支援）。無論完全或選擇性隔離，裝置與 Defender 雲端服務的通道都會保留，所以隔離後仍可繼續調查、收集調查套件或開啟即時回應（Live Response）。

  • A：完全隔離會切斷除了 Defender 通道以外的所有網路連線，Teams 與 Outlook 都不通，服務台無法聯絡使用者，不符合題目要求。
  • C：限制應用程式執行套用的是程式碼完整性原則，只允許 Microsoft 簽章的檔案執行，網路照樣暢通——它擋的是「執行權」而不是「連線」，達不到阻止裝置存取其他資源的目的。
  • D：contain device 是給「探索到但未上線、裝不了代理程式」的裝置用的：命令已上線裝置拒絕與它通訊。本題筆電已上線，可以直接下隔離動作。

QUESTION 2 · D2-0007
During an investigation you open a live response session on a compromised device. The session connects and the processes and getfile commands work, but you cannot execute your own unsigned PowerShell collection script. You must be able to run that script on the device during this investigation. What should you request?
（調查期間你在受害裝置上開啟即時回應（Live Response）工作階段。工作階段順利連上，processes 與 getfile 命令也能用，但你無法執行自己撰寫、未簽章的 PowerShell 蒐證指令碼。你必須能在這次調查中於該裝置上執行這支指令碼。你應該要求什麼？）
A. Unrestricted (advanced) live response permissions for your role, the Live response unsigned script execution advanced feature turned on, and the script uploaded to the live response library
為你的角色授予進階（unrestricted）即時回應權限、開啟「Live response unsigned script execution」進階功能，並把指令碼上傳到 live response library
B. The Live response for servers advanced feature turned on for the tenant
為租用戶開啟「Live response for servers」進階功能
C. A collect investigation package action on the device so that you can analyse the output offline
改對裝置執行收集調查套件（collect investigation package），把輸出帶回離線分析
D. The active remediation actions permission that is required to isolate devices
取得執行裝置隔離所需的「主動修復動作」權限
看正解與解析
正解：A

即時回應命令分兩級：唯讀類（cd、dir、fileinfo、processes、connections、registry、getfile 等）屬基本（basic），會改變裝置或把東西放進裝置的（putfile、run、remediate、undo、library、analyze）屬進階（unrestricted）。指令碼跑不動的三層檢查正好對應本題：缺進階權限、未簽章指令碼需要開啟 Live response unsigned script execution、以及 run 只能執行 library 內的檔案，所以指令碼必須先上傳。

  • B：Live response for servers 決定的是「能不能對伺服器開工作階段」。本題工作階段已經成功建立，問題出在命令層級的權限與指令碼來源，不是伺服器開關。
  • C：調查套件是一次性打包 autoruns、處理程序、網路連線、排程工作與事件記錄檔的唯讀鑑識快照，無法執行你的自訂邏輯，也不能在裝置上互動蒐證。
  • D：主動修復動作權限管的是隔離、限制執行、防毒掃描這類裝置動作，與即時回應的基本／進階命令權限是不同的權限項目，給了也不會讓 run 可用。

QUESTION 3 · D2-0008
An automated investigation that was triggered by a malware alert has been in the Pending approval state for two hours, and the malicious file is still present on the device. You must complete the remediation with the least delay and keep an audit trail of who authorized it. What should you do FIRST?
（由惡意程式碼警示觸發的自動調查已經停在「Pending approval（待核准）」狀態兩小時，惡意檔案仍留在裝置上。你必須以最短的延遲完成修復，並保留是誰核准的稽核軌跡。你應該「最先」做什麼？）
A. Set the automation level of the device group to No automated response and remediate the file manually
把該裝置群組的自動化層級改為 No automated response，改以人工修復該檔案
B. Start another automated investigation from the device page
從裝置頁再啟動一次自動調查
C. Open the Action center, review the pending remediation actions, and approve them
開啟 Action center，檢視待核准的修復動作並核准它們
D. Use the History tab of the Action center to undo the actions of the investigation
使用 Action center 的歷史紀錄（History）索引標籤復原（undo）該調查的動作
看正解與解析
正解：C

「Pending approval」代表裝置群組的自動化層級是 semi，自動調查已經完成判定、也備好修復動作，只是卡在等人核准。最快的路徑是到 Action center 的待核准清單檢視並核准；Action center 會記錄誰在何時核准了哪個動作，同時滿足稽核需求，而且事後若判定有誤還能從歷史紀錄 undo。若這類延遲常態化，再考慮把該群組調成 full。

  • A：No automated response 會讓自動調查完全不啟動，等於連現成的判定與修復建議都放棄，只會讓後續每一次事件都更慢，不是「最短延遲」的作法。
  • B：再跑一次調查同樣會停在待核准，因為卡住的原因是自動化層級需要核准，不是調查失敗；重跑只是浪費時間。
  • D：undo 用於復原「已經執行完」的動作（例如解除隔離、從隔離區還原檔案）。這裡動作根本還沒執行，沒有東西可以復原。

QUESTION 4 · D2-0009
A production line controller that runs Windows Server generates alerts for an unknown binary. The operations team states that the server must keep its network connections to the line equipment, because losing them halts manufacturing. You must stop the unknown binary from running while you preserve volatile evidence. What should you do?
（一台執行 Windows Server 的產線控制器針對一個不明二進位檔產生警示。維運團隊表示這台伺服器必須保持與產線設備的網路連線，一旦中斷就會停產。你必須在保留揮發性證據的前提下，阻止這個不明二進位檔繼續執行。你應該怎麼做？）
A. Isolate the server by using full isolation, then collect an investigation package
先以完全隔離隔離該伺服器，再收集調查套件
B. Isolate the server by using selective isolation so that Outlook and Teams keep working
以選擇性隔離隔離該伺服器，讓 Outlook 與 Teams 仍可運作
C. Run a full antivirus scan and wait for the result before taking any other action
先執行完整防毒掃描，等結果出來再決定其他動作
D. Restrict app execution on the server, then collect an investigation package
對該伺服器套用限制應用程式執行，再收集調查套件
看正解與解析
正解：D

一般情況下順序是「先隔離再取證」，因為 MDE 的隔離保留了與 Defender 服務的通道，取證能力不受影響。但題幹明說「網路服務不能中斷」，此時最佳解是限制應用程式執行：它套用程式碼完整性原則，只允許 Microsoft 簽發憑證簽章的檔案執行，擋掉不明二進位檔卻不動網路，再立刻收集調查套件保存 autoruns、處理程序、網路連線與事件記錄檔等揮發性證據。事後要解除也有對應的 Remove app restriction。

  • A：完全隔離會切斷除 Defender 通道外的所有連線，等於讓產線停擺，直接違反題目給的營運限制。
  • B：選擇性隔離只是保留 Outlook／Teams／Skype for Business，與產線設備的通訊照樣被切斷；而且它僅限較新版 Windows 用戶端，伺服器不支援。
  • C：只跑防毒掃描既不保證能立刻攔下未知的二進位檔（可能沒有對應偵測），等待期間程式仍在執行，遏制被延後，也沒有先保存揮發性證據。

QUESTION 5 · D2-0010
Your malware analysis team asks you to hand over the actual suspicious executable from an infected device so that they can detonate it in their own sandbox. The device is currently isolated, and the file must remain unchanged on the device for now. Which action retrieves the file for offline analysis?
（惡意程式分析小組要求你把受害裝置上那個可疑執行檔本體交給他們，讓他們在自家沙箱中引爆分析。該裝置目前處於隔離狀態，而且該檔案暫時必須原封不動留在裝置上。哪一個動作可以取回檔案供離線分析？）
A. Start a live response session and use the getfile command
開啟即時回應工作階段，使用 getfile 命令
B. Run Collect investigation package on the device and download the ZIP package
對裝置執行收集調查套件，再下載該 ZIP 封裝
C. Run Stop and quarantine file on the file hash
針對該檔案雜湊執行 stop and quarantine file
D. Create a Block and remediate file indicator for the SHA256 of the file
為該檔案的 SHA256 建立 Block and remediate 檔案指標
看正解與解析
正解：A

getfile 是把裝置上的單一檔案取回供離線分析的取證主力命令，屬基本（basic）權限層級；而且裝置在隔離狀態下仍保有與 Defender 服務的通道，即時回應照常可用。高頻對比句型：「把可疑執行檔送沙箱分析」→ getfile；「保存整台機器的完整鑑識資料」→ collect investigation package。

  • B：調查套件打包的是 autoruns、處理程序、網路連線與 DNS／ARP 快取、排程工作、服務、prefetch、安全性事件記錄檔等鑑識產物，不含你指定的那個惡意執行檔本體。
  • C：stop and quarantine file 會停止處理程序並在租用戶範圍內把檔案移入隔離區，等於改變了裝置上的檔案狀態，違反「暫時原封不動」的要求，也不會把檔案交到分析小組手上。
  • D：檔案指標是持續性的封鎖規則，讓同一個雜湊未來再出現就被擋下（Block and remediate 還會一併清除），屬於預防擴散的手段，不是取檔手段。
