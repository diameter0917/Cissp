曉臻：哈囉，歡迎收聽 SC-200 速成電台，我是曉臻。接下來八週，我們每天陪你十分鐘，把 Microsoft 安全分析師認證一次拿下。

雲哲：大家好，我是雲哲。第一天我們不急著講設定，先把整張地圖攤開來看。

曉臻：對，今天的主題是「考試全景與 Microsoft 安全生態系」。雲哲，先給聽眾今天的三個重點吧。

雲哲：好。第一，考綱三大領域跟權重，你要知道分數藏在哪裡。第二，Defender 家族跟 Sentinel 到底誰管什麼。第三，考試怎麼考，包括可以翻 MS Learn 的開卷政策。

曉臻：那就從大家最常見的困惑開始：微軟的安全產品名字都好像，Defender 這個、Defender 那個，到底怎麼分？

雲哲：記一句話就好：四個 Defender 各守一面牆。MDE 是 Defender for Endpoint，守裝置；MDO 守 Office 365 的信箱；MDI 守內部的 Active Directory 身分識別；MDA 守 SaaS 雲端應用。

曉臻：那 Defender XDR 呢？它是第五面牆嗎？

雲哲：不是，XDR 是把四面牆連成一個房間的整合層。它會自動把不同產品的警示關聯成同一個事件，你在一個入口就能看到攻擊全貌。

曉臻：所以我在畫面上看到的不是一百條警示，而是一筆事件？

雲哲：對，這就是 XDR 的價值。我以前待的 SOC 還沒有這種整合，一個釣魚案要開四個視窗自己拼圖，現在平台直接幫你拼好。

曉臻：那 Sentinel 是什麼角色？跟 XDR 不會重複嗎？

雲哲：一句話：XDR 深、Sentinel 廣。Sentinel 是雲原生的 SIEM 加 SOAR，負責把微軟以外的東西，像防火牆、Syslog、其他雲的記錄，全部收進工作區，再疊上分析規則跟自動化。

曉臻：SIEM 跟 SOAR 這兩個詞，第一次聽的人可以怎麼理解？

雲哲：SIEM 是收集加偵測，把全公司的記錄集中起來找異常；SOAR 是回應自動化，偵測到之後自動開單、隔離、通知。Sentinel 兩個都做。

曉臻：還有一個新面孔 Security Copilot，它就是個聊天機器人嗎？

雲哲：不只，它是 AI 副駕駛。可以幫你摘要事件、寫 KQL 查詢、引導回應步驟，現在還有 agents，可以自主跑完分診這類流程。這是 2026 考綱的新重點。

曉臻：好，地圖有了。那考試本身呢？三大領域是哪三個？

雲哲：D1 管理安全性作業環境，占 40 到 45%，考環境怎麼架，Defender 跟 Sentinel 的設定、資料連接器、data lake 都在這。D2 回應安全性事件，占 35 到 40%。D3 執行威脅搜捕，占 20 到 25%，主力是 KQL。

曉臻：D1 居然最重？我以為回應事件才是主角。

雲哲：很多人意外。但你想，環境沒架好，警示根本進不來，談什麼回應？而且 2026 版把 data lake 跟 Copilot 的管理面都放進 D1，它就更肥了。

曉臻：以 55 題來算，D1 大概就是 22 到 25 題，確實不能放掉。那 SOC 分析師的一天長什麼樣？

雲哲：SOC 通常分三層。Tier 1 做分診，盯著事件佇列判斷真假警報；Tier 2 做深入調查跟回應，隔離裝置、重設密碼都在這層；Tier 3 做威脅搜捕，主動找還沒變成警示的威脅。

曉臻：考試會偏向哪一層嗎？

雲哲：三層都考，而且題目常用 You are a security operations analyst 開場，然後問你下一步該做什麼。所以要習慣代入角色想事情，選最符合這個角色的答案。

曉臻：事件生命週期也幫大家走一遍吧。

雲哲：六個站：偵測、分診、調查、遏制回應、復原、事後學習。重點是它是圓的，最後的學習會回頭調校偵測規則。我們五週的課程安排，其實就是沿著這條線走。

曉臻：好，最實際的問題來了：考試到底怎麼考？幾題？多久？

雲哲：大約 40 到 60 題、100 分鐘，單選、多選、拖放、案例研究都有。1000 分裡拿 700 及格，答錯不倒扣，所以絕對不要留空白。

曉臻：聽說考試中可以翻 Microsoft Learn，是真的嗎？

雲哲：真的，但時間算在你的 100 分鐘裡。我的建議是把它當保險，只查記不住的數字型細節，像保留期上限那種。平常就要練到八成題目不翻書也能答。

曉臻：2026 新考點除了 Copilot，還有哪些要注意？

雲哲：一共六個：內嵌 Security Copilot 跟 agentic AI、Sentinel data lake、summary rules、KQL jobs、Sentinel Graph，還有 Sentinel MCP Server。都有專屬單元，第二週跟第五週會集中處理。

曉臻：好，進入考點快問快答！第一題：使用者回報收到釣魚郵件，要調查跟修復，該用哪個產品？

雲哲：Defender for Office 365，就是 MDO。信箱的事都找它，之後第三週會學它的 Threat Explorer 跟郵件修復動作。

曉臻：第二題：公司要把第三方防火牆的記錄收進來做關聯分析，靠 Defender XDR 就夠了嗎？

雲哲：不夠，這是 Sentinel 的工作。XDR 只整合微軟自家訊號，第三方資料要靠 Sentinel 的資料連接器收進工作區。這個分界考試超愛考。

曉臻：第三題，是非題：SC-200 的及格線 700 分，意思是要答對七成的題目？

雲哲：錯。700 是量尺分數，不等於答對 70%，每題的難度權重不一樣。所以別在考場上自己心算過不過，把每一題答完才是正解。

曉臻：三題都答對的話，今天的核心你已經抓住了。雲哲，幫大家收個尾？

雲哲：記住三件事：四個 Defender 各守一面牆、XDR 深 Sentinel 廣、D1 權重最高別輕敵。地圖在手，之後每天我們都在地圖上插一面旗。

曉臻：明天進入整個課程的地基：KQL 查詢語言，where、project、summarize 三板斧一次學會。它貫穿三大領域，千萬別缺席，我們明天見！

雲哲：明天見！

KQL 基礎 I：查詢結構與三大運算子
展開逐字稿

曉臻：哈囉，歡迎回到 SC-200 速成電台，我是曉臻。今天是 Day 2，我們要進入整個課程最重要的地基——KQL。

雲哲：我是雲哲。KQL 全名 Kusto Query Language，你可以把它想成資安世界的 Excel 篩選加上樞紐分析，只是威力大非常多。

曉臻：我知道很多人一聽到「查詢語言」就緊張，是不是要會寫程式才學得起來？

雲哲：完全不用。KQL 的設計就是給分析師用的，它讀起來很像在描述你想看什麼資料。今天聽完你會發現它意外地直覺。

曉臻：先給大家今天的三個重點。第一，KQL 的管線思維，就是查詢裡那個直槓符號在做什麼。

雲哲：第二，三大核心運算子：where 篩選、project 挑欄位、summarize 做統計。日常九成的查詢就靠這三個。

曉臻：第三，考試最愛考的細節：字串比對運算子的差異，還有 bin 函式的時間分桶。

雲哲：這集聽完再回去讀今天的電子報，裡面那四段查詢範例你就全部看得懂了。

曉臻：好，從管線講起。雲哲，查詢裡一根一根的直槓，到底是什麼概念？

雲哲：你想像自助餐的動線。資料表是整排菜檯，where 是你只走向想吃的那幾道菜，project 是每道菜只夾要吃的部分，最後 summarize 是結帳阿姨幫你算總共幾樣、多少錢。

曉臻：所以資料是從上面一路流下來，每經過一個直槓就被加工一次？

雲哲：對，上一步的輸出就是下一步的輸入，順序很重要。這也是為什麼要「先 where 再做其他事」——在動線最前面就把不要的資料淘汰掉，後面每一步都輕鬆。

曉臻：那資料表有哪些？昨天介紹的那些產品，各自的紀錄放在哪張表？

雲哲：幾個常客要記：Entra ID 的登入紀錄在 SigninLogs，Windows 安全性事件在 SecurityEvent，Defender for Endpoint 的裝置遙測是 Device 開頭那一個家族，像 DeviceProcessEvents，郵件則是 EmailEvents，來自 Defender for Office 365。

曉臻：考試會考「哪個資料表查什麼」嗎？

雲哲：很常考。題目說要查可疑的 PowerShell 命令列，你要反射性想到 DeviceProcessEvents；說要查釣魚郵件，就是 EmailEvents。表名本身就是答案的一半。

曉臻：我讀電子報有注意到，有的表時間欄位叫 Timestamp，有的叫 TimeGenerated，這是怎麼回事？

雲哲：好問題。Defender 入口網站做進階搜捕，Device 跟 Email 那些表用 Timestamp；Sentinel 的工作區查詢，像 SigninLogs，用 TimeGenerated。語言一樣，但看到欄位名你就知道題目讓你站在哪個入口。

曉臻：了解。那進入第一個運算子 where。它就是設條件篩選嘛，有什麼好講的？

雲哲：魔鬼在字串比對。兩個等號是精確比對而且分大小寫；等號加波浪號是不分大小寫。考題常放一個全大寫的檔名，你用兩個等號就什麼都查不到。

曉臻：哇，這種陷阱好陰險。那 contains 跟 has 呢？文件上都翻成「包含」。

雲哲：差別在比對單位。contains 是任意子字串都算；has 是以完整詞為單位，而且 has 吃得到索引，速度快很多。官方最佳做法就一句話：能用 has 就不要用 contains。

曉臻：所以效能考點就是：先用時間過濾，然後用 has 不用 contains？

雲哲：對。時間過濾用 ago 函式，例如 ago 括號 7d 就是過去七天。每支查詢的第一行，先把時間範圍縮起來，這是鐵律。

曉臻：好，第二個運算子，project。

雲哲：project 就是挑欄位。一張表幾十個欄位，你查案只需要五個，project 點名誰就留誰，還可以順便改名。相反的 project-away 是點名誰就丟誰。

曉臻：那如果我想「加」一個新欄位呢？比如算兩個時間的差。

雲哲：那是 extend 的工作。extend 保留原本所有欄位，再多算一個新欄位；project 是只留你指定的。記口訣：extend 加欄位、project 挑欄位，這差異考試常客。

曉臻：最後一個，summarize。聽名字是在做摘要？

雲哲：它就是 KQL 的樞紐分析表。count 算筆數，dcount 算不重複的個數，countif 是符合條件才算，後面接 by 表示照什麼分組。

曉臻：dcount 算不重複的個數，什麼場景用得到？

雲哲：抓 password spray 超好用。攻擊者用一個 IP 對很多個不同帳號各試一次密碼，你就 summarize dcount 使用者帳號 by 來源 IP，數字異常大的 IP 馬上浮出來。

曉臻：那 bin 呢？開頭重點預告有它。

雲哲：bin 是時間分桶。把連續的時間切成一小時或一天一格，配著 summarize 用，你就能看出每小時失敗登入幾次這種趨勢，有沒有暴增的尖峰一眼就看到。

曉臻：統計完想看前十名怎麼辦？

雲哲：top 10 by 某個欄位，等於先排序再取前十。單獨的 take 只是隨便抓幾筆回來看格式用的，它不保證順序，這個差異也考過。

曉臻：好，進入考點快問快答！第一題：想在命令列裡找 mimikatz 這個完整字詞，效能最好的是 contains 還是 has？

雲哲：has。完整詞比對又能利用索引；contains 是逐字元掃子字串，大表上慢一個量級。

曉臻：第二題：summarize count 括號 by bin 括號 TimeGenerated 逗號 1d，這句在做什麼？

雲哲：把資料照「天」分桶，算出每一天各有幾筆紀錄。要畫每日趨勢圖，就靠這一句。

曉臻：第三題：我要新增一個計算欄位，但原本的欄位都要保留，用 project 還是 extend？

雲哲：extend。project 會把你沒點名的欄位全部丟掉。再念一次口訣：extend 加、project 挑。

曉臻：三題全對！今天的 KQL 地基就打到這裡，明天呢？

雲哲：明天是 KQL 基礎第二集：join 和 union，怎麼把兩張表接起來查，還有 parse 解析欄位、let 變數。搜捕真正的火力從那裡開始。

曉臻：記得先把今天電子報的四段查詢看熟，明天才接得上。我們明天見！

雲哲：明天見，掰掰！

EP3 · P1-W1-3 · 7:24
KQL 基礎 II：join、union 與時間序列
展開逐字稿

曉臻：哈囉，歡迎回到 SC-200 速成電台，我是曉臻。昨天聽完 KQL 第一課，你有沒有真的打開查詢視窗跑跑看？

雲哲：我是雲哲。昨天我們在一張表裡面玩 where、project、summarize，今天要跨出去了——join、union、parse，還有時間序列異常偵測。

曉臻：先講今天三個重點吧。

雲哲：第一，join 的六種 kind，尤其是預設值這個大陷阱。第二，parse 家族，把髒欄位煉成乾淨欄位。第三，arg_max 加上 make-series，一個管去重、一個管抓異常。

曉臻：好，從 join 開始。你先講講，為什麼搜捕一定要學 join？

雲哲：因為攻擊鏈從來不會乖乖待在一張表。釣魚信在 EmailEvents，帳號登入在 IdentityLogonEvents，端點行為在 DeviceLogonEvents。你要把一條線串起來，就得把表跟表關聯。

曉臻：join 有六種 kind，聽起來就很容易搞混。有沒有生活化的講法？

雲哲：有，用「老師改作業」想像。左手一份全班名單，右手一疊交上來的作業。不同的 kind，就是不同的對名單方式。

曉臻：來，先講預設的 innerunique。

雲哲：innerunique 像書展換贈品。同一個同學名字在左邊名單出現三次，先去重、只算一次，然後去右邊找有沒有交作業，兩邊都有的才留下來。

曉臻：等等，所以預設不是 inner？很多人以為不寫 kind 就是一般的 inner join 耶。

雲哲：這就是考試最愛的陷阱！KQL 預設是 innerunique，左表的重複鍵值會先被去掉，筆數會比你想的少。要每一筆都配對，就要自己寫 kind 等於 inner。

曉臻：那 leftouter 呢？

雲哲：leftouter 就是點名。全班名單通通保留，有交作業的旁邊註記分數，沒交的欄位留空白。重點是左表一個都不會少。

曉臻：那如果我只想要「沒交作業的名單」呢？

雲哲：那就是 leftanti——只留左表裡「配不到右表」的列。搜捕上超常用：有登入紀錄、但不在 MFA 已註冊清單裡的帳號，一行 leftanti 就抓出來。

曉臻：所以口訣是：全部保留用 leftouter，只要沒配到的用 leftanti？

雲哲：對。再補一個 leftsemi，它是「右表當門票清單」——只放行左表裡有配到的列，而且右表的欄位完全不帶進來，適合拿 IoC 清單純過濾。

曉臻：join 還有什麼效能上要注意的嗎？

雲哲：三個原則：小表放左邊、join 之前先用 where 把兩邊都過濾瘦身、鍵名不一樣就用 dollar left、dollar right 明確指定。這在官方 best practices 文件裡，考效能題就考這個。

曉臻：OK，那 union 跟 join 差在哪？一句話講清楚。

雲哲：join 是橫向拼欄位，union 是縱向疊資料。拿到一個檔案雜湊不知道在哪張表？union 加萬用字元，Device 星號，所有端點表一次撒網，再配 withsource 標記命中的是哪張表。

曉臻：接下來是 parse 家族。先說一個實際場景吧。

雲哲：最經典的是 syslog。整條訊息是一大串字串，裡面藏著帳號跟來源 IP。用 parse 給它一個文字樣板，星號、關鍵字、欄位名，一行就把帳號和 IP 切出來變成欄位。

曉臻：那什麼時候用 extract？

雲哲：格式固定用 parse，格式亂七八糟就用 extract 寫正規表示式。要抓全部符合的，用 extract underscore all，回傳一個陣列。

曉臻：我知道還有一個大坑——JSON 欄位對吧？

雲哲：對，這個一定要記。有些欄位長得像 JSON，型別其實是字串，比如 DeviceLogonEvents 的 AdditionalFields。你直接點屬性，拿到的是空值，不會報錯，超陰險。

曉臻：所以要先轉型？

雲哲：先用 todynamic 或 parse underscore json 轉成 dynamic，再點屬性，最後用 tostring 或 tobool 收尾。口訣：先轉 dynamic、再點、再轉回來。

曉臻：好，換 arg_max。這個聽說是 SOC 日常神器？

雲哲：每天都在用。需求是「每台裝置只要最新一筆登入」。寫 summarize arg_max，第一個參數放 Timestamp，第二個放星號，再 by DeviceId，每台裝置就只剩時間最新的那一列。

曉臻：那個星號是什麼意思？

雲哲：星號代表「那一列的所有欄位整列帶走」。這跟 max 差很多——max 只回傳最大的時間值，帳號、IP 全部丟光。要完整紀錄，一定是 arg_max。

曉臻：反過來要「第一次出現」呢？

雲哲：arg_min。帳號第一次登入某台裝置的時間點，搜捕橫向移動起點的時候超好用。

曉臻：最後一塊，時間序列異常偵測。這個聽起來最難。

雲哲：概念其實簡單：先用 make-series 把事件變成等間隔的數列，比如每小時的登入失敗次數，沒事件的時段用 default 補零。再丟給 series underscore decompose underscore anomalies，它會拆出基線，把異常尖峰標成 1。

曉臻：跟昨天學的 bin 分桶差在哪？

雲哲：記住四件事：join 預設是 innerunique；找缺席用 leftanti；JSON 字串先 todynamic 再點屬性；每個實體取最新一筆用 arg_max。這四招就是明天開始所有跨表搜捕的地基。

曉臻：考題怎麼分辨？

雲哲：題目說最小權限、有時效、可控管，答案就是 GDAP。干擾項會放 DAP、放在客戶租用戶開 Global Administrator 帳號、放共用帳號，全部違反最小權限或可歸責性。

雲哲：租用戶邊界。Defender XDR 這種第一方連接器只能連同租用戶的工作區。多租用戶集團或 MSSP 的客戶，每個租用戶都得有自己的工作區。第三個是拆帳：各子公司要自己付擷取帳單，分開最乾淨。

曉臻：MSSP 要顧十個客戶的工作區，總不能十個帳號輪流登入吧？

雲哲：關鍵字 Azure Lighthouse。客戶把工作區所在資源群組的特定角色委派給服務商租用戶，MSSP 分析師在自己家登入，就能同時查詢、分診所有客戶的工作區。

曉臻：昨天才講過 GDAP，跟 Lighthouse 差在哪？

雲哲：GDAP 委派 Entra 角色，管 Microsoft 365 跟 Defender XDR 那個世界；Lighthouse 委派 Azure RBAC。Sentinel 工作區是 Azure 資源，所以代管 Sentinel 找 Lighthouse。

曉臻：清楚。進第二個重點，Sentinel 的角色有哪幾個？

雲哲：四個專屬角色，用動詞記。Reader 只能看；Responder 可以動事件，指派、改狀態、關閉；Contributor 可以動內容，建分析規則、編活頁簿。一個比一個大。

曉臻：第四個 Automation Contributor，聽名字像自動化工程師要拿的？

雲哲：這就是陷阱。它不是給人的，是給 Sentinel 服務本身，讓它有權把劇本掛進自動化規則。題目說「指派給某位人員」，這選項直接刪掉。

曉臻：情境題：夜班分析師要分診事件、改狀態，但不准動偵測規則，給哪個？

雲哲：Responder。給 Contributor 就違反最小權限，因為他能改分析規則。跟昨天一樣：抓動詞，選剛剛好的那個。

曉臻：那如果只想讓應用團隊看自己那台伺服器的記錄呢？

雲哲：兩個細粒度機制。resource-context RBAC：對資源本身有讀取權，就能查那個資源產生的記錄，不用工作區權限。table-level RBAC：用自訂角色把讀取權縮到特定資料表。

曉臻：怎麼分？

雲哲：「只能看自己資源的記錄」選 resource-context；「只能查特定資料表」選 table-level。兩個關鍵字對兩個機制，別互換。

曉臻：第三個重點，錢。Sentinel 怎麼計費？

雲哲：主體是擷取量，資料進工作區按 GB 收錢。第一顆旋鈕：承諾層級。每天穩定吃 100 GB 以上，就跟微軟承諾一個量換折扣，層級越高折扣越深。

曉臻：承諾了可以反悔嗎？

雲哲：往上調隨時可以，往下調要等 31 天承諾期滿。用不滿還是照承諾量收費，所以先觀察實際用量再承諾。

曉臻：第二顆旋鈕，表方案是什麼概念？

雲哲：不是每種記錄都值得付全功能的價錢。Analytics 是頭等艙，完整 KQL、能觸發分析規則，給高價值安全訊號。Basic 是經濟艙，擷取便宜但查詢受限、另外計費。Auxiliary 是貨艙，單價最低，給幾乎只為合規留著的 verbose 記錄。

曉臻：那我全部改成 Auxiliary，不就超省？

雲哲：省到偵測直接瞎掉。Basic 跟 Auxiliary 都不支援排程分析規則，把 SecurityEvent 丟過去，規則就不觸發了。省錢題的反向陷阱：偵測賴以運作的表，不能降艙等。

曉臻：還有一招免費的對吧？

雲哲：有些來源不收擷取費：Azure 活動記錄、Office 365 稽核記錄、Defender 全家的警示。考題問「斷開哪個連接器省錢」，這幾個免費來源一律不是答案，斷了也省不到錢。

曉臻：第三顆旋鈕，保留期。聽說有兩層設定？

雲哲：工作區預設保留套所有表，表級保留可以覆寫。資料有兩種狀態：互動保留是熱的，KQL 隨查隨到，Sentinel 工作區前 90 天免費；期滿轉長期保留，便宜很多，最長留 12 年。

曉臻：長期保留不能直接查，要查怎麼辦？

雲哲：兩條路。search job：非同步掃描，用受限 KQL 撈一次，結果寫進新表，適合在一年前的記錄裡找 IOC。restore：把某段時間整段還原回互動狀態，完整查詢能力，適合深挖那兩週，按量計費，查完記得刪。

曉臻：口訣：撈針用 search job，翻土用 restore。那環境本身健不健康誰來看？

雲哲：SentinelHealth。啟用健康監控後，這張表記錄連接器、分析規則、自動化的健康事件，連接器斷線第一時間知道。注意它不是預設全開，要先在設定啟用。

曉臻：最後補 2026 重點：這些都搬進 Defender portal 了？

雲哲：對。工作區連入之後，事件跟 XDR 同一條佇列；多個工作區可以都連入，指定一個主要工作區做關聯。Azure portal 體驗 2026 年 7 月退場，但底層的工作區、角色、成本保留設定全部不變。

曉臻：快問快答，三題。第一題：法規要求歐盟子公司的記錄不得離開歐盟，工作區怎麼設計？

雲哲：在歐盟區域建獨立工作區。工作區綁區域，資料主權是逼你開多工作區的第一訊號。

曉臻：第二題，是非題：分析師只需要分診事件，給 Microsoft Sentinel Contributor 是最小權限的正解？

雲哲：錯。Contributor 能改分析規則，超出需求，正解是 Responder。動事件選 Responder，動內容才選 Contributor。

曉臻：第三題：大量防火牆 verbose 記錄，不用於即時偵測，只為合規留一年，放哪個表方案？

雲哲：Auxiliary logs 加長期保留，查歷史跑 search job；需要餵偵測的聚合統計，用 summary rules 送回 Analytics 表。

曉臻：三題全對，地基就打穩了。明天預告？

雲哲：工作區蓋好，明天接水電：資料連接器。Content Hub 解決方案、Defender XDR 跟 Entra 的第一方連接器，還有資料收集規則 DCR，都是 D1 大考點。

曉臻：倉庫蓋好了，明天開始進貨。我們明天見！

雲哲：明天見！

EP7 · P1-W2-2 · 8:18
資料連接器與 DCR
展開逐字稿

曉臻：哈囉大家好，歡迎回到 SC-200 速成電台，我是曉臻。昨天把工作區設計好了，蓄水池挖好了，今天呢？

雲哲：我是雲哲。今天接水管。工作區空著沒用，要靠資料連接器把記錄灌進來，Sentinel 才有東西可以偵測。

曉臻：老規矩，先給三個今日重點。

雲哲：第一，Content Hub 內容中樞：現在不是逐個接連接器，是逐包裝解決方案。第二，四大第一方連接器：Defender XDR、Entra ID、Office 365、Azure Activity，各帶什麼表、要什麼授權、哪些免費。第三，DCR 資料收集規則跟擷取時轉換，這是今天最值錢的考點，直接關係到帳單。

曉臻：先從 Content Hub 開始。它跟以前的連接器清單差在哪？

雲哲：差在打包。內容中樞裡的單位叫解決方案，solution。你裝一個解決方案，裡面不只有連接器，還有現成的分析規則範本、活頁簿、搜捕查詢，有些還帶劇本跟剖析器。

曉臻：所以裝一包，偵測跟儀表板都到位了？

雲哲：內容到位，但有個坑：安裝不等於連線。裝完解決方案，連接器還要再設定一次才真的有資料進來。考題說裝了解決方案卻沒資料，答案就是連接器還沒設定。

曉臻：還有一個動詞吧？規則範本也要啟用？

雲哲：對，三個動詞分清楚：安裝解決方案、設定連接器、啟用規則範本。三步都做完，水才會流、警示才會響。

曉臻：進第二個重點，第一方連接器。先講最重要的一個？

雲哲：Defender XDR 連接器，而且它有兩層資料，考試最愛考這個。第一層是事件跟警示，免擷取費，還會雙向同步狀態。第二層是進階搜捕的原始事件表，像 DeviceProcessEvents、EmailEvents 這些。

曉臻：第二層聽起來很香，全勾起來不就好了？

雲哲：第二層要付擷取費，而且量非常大。所以答題公式是：題目只要統一分診事件，接連接器就好；題目要對原始表寫自訂規則、或留超過 30 天做長期搜捕，才加勾事件收集，而且要先估成本。

曉臻：那 Entra ID 連接器呢？

雲哲：帶 SigninLogs 跟 AuditLogs，登入記錄跟稽核記錄。考點在授權：匯出登入記錄需要 Entra ID P1 或 P2。題目說接了連接器但 SigninLogs 一直是空的，先檢查授權。

曉臻：Office 365 跟 Azure Activity 這兩個呢？

雲哲：兩個都免費，必接。Office 365 帶 OfficeActivity 表，Exchange、SharePoint、Teams 的活動記錄。Azure Activity 帶訂用帳戶的控制平面稽核，誰開了機器、誰改了防火牆規則。

曉臻：Azure Activity 有個新版設定方式要記？

雲哲：對，新版連接器是透過 Azure Policy 把診斷設定大規模套到所有訂用帳戶。考綱明寫這條。記口訣：活動、辦公、警示免費；登入、原始事件收費。

曉臻：好，第三個重點，DCR。你先講講它跟代理程式的關係？

雲哲：用水來比喻。連接器是水管，把水引進蓄水池。裝在機器上的 Azure Monitor Agent，AMA，本身是個無腦的抽水機，它自己不知道要收什麼。

曉臻：那誰告訴它？

雲哲：DCR，資料收集規則。一條 DCR 是三段式：資料來源，收什麼；轉換，入庫前怎麼加工；目的地，送到哪個工作區。然後把 DCR 關聯到機器上，一條規則可以管幾百台，一台機器也可以掛好幾條。

曉臻：中間那段轉換，就是你說直接關係到帳單的部分？

雲哲：對，擷取時轉換，transformKql。如果說連接器是水管，這就是裝在水管上的濾水器，水進池子之前先過濾。它能做三件事：過濾雜訊、遮罩敏感欄位、砍掉肥大欄位。

曉臻：一件一件講。過濾雜訊怎麼省錢？

雲哲：Sentinel 是按擷取量計費的。像 Windows 的 5156 這種防火牆連線事件，量超大、偵測價值超低，用一行 where 在入庫前丟掉，那些量就完全不計費。這是省錢主力。

曉臻：遮罩呢？為什麼要在入庫前做？

雲哲：因為入庫前遮掉，工作區裡從頭到尾就不存在那個敏感值，比如把 IP 最後一段換成星號。事後遮是遮不乾淨的，稽核就看這個。

曉臻：有沒有什麼限制要注意？

雲哲：兩個。第一，transformKql 只能用 KQL 子集，輸入固定叫 source，不能 join 別的表。第二，成本細則：過濾掉的量超過五成，超過的部分反而要收資料處理費。所以要丟九成的量，正確做法是回到來源端別收，而不是靠轉換硬砍。

曉臻：那如果資料不是 AMA 收的，是 Entra ID 這種雲端直送的，濾水器裝哪？

雲哲：問得好，這就是工作區轉換 DCR。每個工作區只有一條，專管不走標準 DCR 的路徑，像 SigninLogs、OfficeActivity 這些連接器直送的表，你在裡面按表定義轉換。

曉臻：所以二選一公式是？

雲哲：先問資料是代理程式收的還是連接器直送的。AMA 收的，轉換寫在標準 DCR；直送的，寫在工作區轉換 DCR。干擾項常放 ASIM，記住 ASIM 是查詢時正規化，資料原封不動入庫，不省錢也遮不了罩。

曉臻：省成本的題目還有別的干擾項套路嗎？

雲哲：有，全是真功能，考你分不分得清作用位置。縮短保留期，只省儲存不省擷取。Summary rules，是把已入庫的資料事後彙總，2026 的新考點。基本記錄跟 data lake 層，是換便宜方案，不是減量。只有擷取時轉換是在入庫前動刀。

曉臻：最後補一塊，連接器接上之後就沒事了嗎？

雲哲：最怕水管默默漏了三天沒人發現。要自動化監控，就在設定裡啟用健康監控，健康事件會寫進 SentinelHealth 這張表，對它寫分析規則，連接器一斷線就開事件通知值班。

曉臻：沒資料進來的排查順序給一下？

雲哲：五步：先查授權，再查權限，再查代理程式心跳跟 DCR 關聯，再查是不是轉換寫錯把資料全濾光了，最後才考慮是不是單純的擷取延遲。

曉臻：進入快問快答，三題。第一題：要在 Sentinel 工作區裡對 DeviceProcessEvents 寫自訂分析規則，接 Defender XDR 連接器時要做什麼？

雲哲：額外勾選進階搜捕的事件收集。只接預設的事件警示層是拿不到原始表的，而且記得這層要付擷取費。

曉臻：第二題，是非題：SigninLogs 想在入庫前遮罩欄位，轉換要寫在收集那台機器的標準 DCR 裡？

雲哲：錯。SigninLogs 是連接器直送的，根本沒有經過任何機器跟標準 DCR，要寫在工作區轉換 DCR，每個工作區就那一條。

曉臻：第三題：預算有限的新 SOC，哪三個連接器先接可以零擷取費拿到基本可見度？

雲哲：Defender XDR 的事件警示、Office 365、Azure Activity，免費三寶。身分很重要的 Entra ID 登入記錄要收費，但通常也是第一週就該花的錢。

曉臻：三題全對，今天的水管跟濾水器就都裝好了。明天預告？

雲哲：明天講連接器下集：非微軟來源。Syslog 跟 CEF 怎麼透過 AMA 轉送進來、自訂記錄怎麼建表，還有 ASIM 正規化，把五花八門的格式整理成同一套結構。

曉臻：微軟的接完了，明天接全世界的。我們明天見！

雲哲：明天見！

EP8 · P1-W2-3 · 7:13
Syslog、CEF 與 ASIM 正規化
展開逐字稿

曉臻：哈囉大家好，歡迎回到 SC-200 速成電台，我是曉臻。昨天把微軟自家的連接器接完了，今天接誰？

雲哲：我是雲哲。今天接比較野的那一群：講 syslog 的 Linux 跟網路設備、講 CEF 的資安設備，還有只會吐 JSON 的自研應用。

曉臻：老規矩，先給三個今日重點。

雲哲：第一，Syslog 跟 CEF 兩條進貨路線跟轉送器架構。第二，自研應用走 Logs Ingestion API，落進 _CL 自訂表。第三，ASIM 正規化，一支查詢跨所有來源，今天最值錢的考點。

曉臻：先講地基，這三條路是不是都繞著同一套機制？

雲哲：對，都是 AMA 加 DCR。AMA 是目前唯一支援的代理程式，舊的 MMA 已經在 2024 年 8 月退場，選項看到它一律淘汰。AMA 自己沒有設定檔，收什麼、送哪去全靠 DCR。

曉臻：那 Syslog 跟 CEF 差在哪？

雲哲：Syslog 是自由格式，整段內文塞在 SyslogMessage 欄位，落在 Syslog 表，用的時候自己剖析。CEF 架在 syslog 之上，標頭加 key=value，落在 CommonSecurityLog，欄位都幫你拆好了。

曉臻：所以誰會講 CEF？

雲哲：防火牆、Proxy、WAF 幾乎都支援。答題公式：題幹說設備支援 CEF，就走 CEF via AMA、查 CommonSecurityLog；只有原生 syslog 才走 Syslog 表。

曉臻：可是防火牆上裝不了代理程式，AMA 到底裝哪？

雲哲：這就是轉送器架構。你架一台 Linux 機器當集散中心，上面跑 rsyslog 或 syslog-ng 監聽 514 埠，再裝 AMA。所有設備把 CEF 指向這台，AMA 依 DCR 往上送。

曉臻：地端機器有沒有前置作業？

雲哲：要先用 Azure Arc 註冊，才裝得了 AMA、掛得上 DCR。架構題的鐵律一句話：AMA 永遠裝在轉送器或 Linux 主機本身，不裝在 appliance 上。

曉臻：陷阱選項通常長什麼樣？

雲哲：三種：把 AMA 裝上防火牆、用已經退場的 MMA、叫防火牆自己去呼叫 API。三個都做不到。

曉臻：這裡還有一個很容易踩的重複計費坑？

雲哲：對。同一台轉送器同時收 Syslog 跟 CEF，兩條 DCR 若勾了重疊的 facility，同一則訊息會寫進兩張表，資料重複、費用雙倍。正解是讓兩條的 facility 互不重疊。

曉臻：接完怎麼確認管線活著？

雲哲：拿 CommonSecurityLog 做健康檢查，依 DeviceVendor、DeviceProduct、Computer 去 summarize 筆數跟 LastSeen。Computer 是轉送器主機名稱，多台時可以看出哪條管線斷了。

曉臻：第二個重點，自研應用怎麼進來？

雲哲：走 Logs Ingestion API，它取代了舊的 HTTP Data Collector API。五個零件：Entra 應用程式註冊做驗證、DCE 當收件地址、DCR 定義結構描述跟轉換、目標是結尾 _CL 的自訂表，最後用 KQL 抽查。

曉臻：還有一個 CCF 是什麼？

雲哲：無程式碼連接器框架，給 SaaS 來源用的。用 JSON 宣告式定義 API 輪詢邏輯，微軟代管的基礎結構去幫你拉資料。方向要分清楚：CCF 是 Sentinel 去拉，Logs Ingestion API 是你的應用主動推。

曉臻：自訂表現在也能選層級？

雲哲：這是 2026 新考點。常查的放分析層；量大、很少查但合規要留的 verbose 記錄放 Sentinel data lake，擷取成本低很多，要調查再撈回來。題目給「一天 200 GB、偶爾調查、成本最小化」就是在考這個。

曉臻：一句話收斂三條路？

雲哲：設備走轉送器、應用走 API、SaaS 走 CCF。終點都一樣：DCR 決定形狀、資料表決定家。

曉臻：第三個重點，ASIM。它要解決什麼問題？

雲哲：同樣是來源 IP，Infoblox 一個名字、Azure Firewall 另一個、Windows DNS 又不一樣。沒有正規化，一條 DNS 偵測規則就得為每個來源各寫一份。

曉臻：ASIM 怎麼解？

雲哲：在查詢時套一層標準結構描述，欄位統一叫 SrcIpAddr、DvcHostname、EventResult，偵測內容一次寫、處處用。常考的 schema 家族有 Network Session、DNS、Authentication、Process Event。

曉臻：重點是查詢時，不是入庫時？

雲哲：對，這點跟昨天的擷取時轉換剛好相反。ASIM 讓資料原封不動入庫，不省錢也不遮罩，它只在查的時候翻譯。

曉臻：翻譯的工人叫剖析器，命名規則是考點吧？

雲哲：三兄弟要分清楚。vim 開頭是來源特定，像 vimDnsInfoblox，只翻一家產品。im 開頭是 unifying，把該 schema 所有來源的 vim union 起來，查一支等於查全部。

曉臻：那 ASim 開頭呢？

雲哲：ASim 是無參數版，先翻完全部資料才讓你 where，適合互動探索，大範圍排程查詢會很慢。im 跟 vim 都是 filtering 剖析器，可以把 starttime、domain_has_any 推到剖析之前，效能最好。

曉臻：底線開頭又代表什麼？

雲哲：底線開頭像 _Im_Dns 是內建版，微軟自動更新；沒底線的 imDns 是你自己從 GitHub 部署到工作區的。答題公式：跨來源選 im、單一來源選 vim、要效能就挑帶參數的。

曉臻：新來源沒有現成剖析器怎麼辦？

雲哲：照 schema 規格寫一支 KQL 函數，把自家欄位對應成標準名稱，再掛進 unifying 剖析器。之後所有建在 ASIM 上的偵測自動涵蓋你的來源，一條規則都不用改。

曉臻：進入快問快答，三題。第一題：地端 Fortinet 防火牆要接進 Sentinel，AMA 裝在哪？資料落在哪張表？

雲哲：AMA 裝在 Linux 轉送器上，防火牆本身裝不了，而且這台地端機器要先用 Azure Arc 註冊。走 CEF，資料落在 CommonSecurityLog。

曉臻：第二題：要寫一條涵蓋所有 DNS 來源的偵測，而且效能要好，用哪個剖析器？

雲哲：_Im_Dns，內建的 unifying filtering 剖析器，把 domain_has_any 當參數傳進去。選 vimDnsInfoblox 只涵蓋一家，選無參數的 ASim 版反而更慢。

曉臻：第三題：自研訂單系統要把 JSON 日誌推進 Sentinel，需要哪些零件？

雲哲：Entra 應用程式註冊、DCE、DCR，再加一張 _CL 自訂表。方向是推，別選 CCF，那是 Sentinel 去拉 SaaS 用的。

曉臻：三題都很扎實。明天預告？

雲哲：明天讓這些記錄長出判斷力：威脅情報。STIX、TAXII 連接器、上傳 API、MDTI，還有 SOC 的合法小抄 watchlists。

雲哲：明天見！

EP9 · P1-W2-4 · 7:28
威脅情報與 Watchlists
展開逐字稿

曉臻：哈囉大家好，歡迎回到 SC-200 速成電台，我是曉臻。昨天把第三方記錄全接進來了，今天要做什麼？

雲哲：我是雲哲。今天讓這些記錄長出判斷力。單看一條對外連線你分不出好壞，但只要目的地 IP 出現在威脅情報清單上，它馬上變成待辦事件。

曉臻：老規矩，三個今日重點。

雲哲：第一，威脅情報生命週期跟四大 IoC 類型。第二，把情資弄進 Sentinel 的三條路：TAXII、上傳 API、MDTI。第三，讓情資真的產生警示的 TI map 規則，還有 SOC 的合法小抄 watchlists。

曉臻：先給個直覺，威脅情報到底是什麼？

雲哲：把它想成氣象預報。它擋不住暴風雨，但能告訴你哪裡在下雨、暴風往哪走，讓你決定要不要收衣服、封港口。

曉臻：生命週期五階段也要背嗎？

雲哲：要記順序：規劃與方向、收集、處理、分析、散播與回饋。今天學的匯入、比對、失效管理，剛好對應收集、散播跟回饋這三段。

曉臻：四大 IoC 類型差在哪？

雲哲：檔案雜湊最精準、幾乎零誤判，但攻擊者改一個位元組就全變，壽命最短。IP 最好比對，可是雲端 IP 輪替快、還可能是共用主機，誤判風險最大。網域壽命中等，URL 最具體但變形最快。

曉臻：所以有什麼共通結論？

雲哲：越容易比對的指標，攻擊者也越容易換掉。所以 IoC 一定要靠持續更新的餵送，而不是一張永久清單，每個指標也都帶有效期跟信賴度，過期要能自動退場。

曉臻：進第二個重點，三條匯入路徑怎麼分？

雲哲：TAXII 是拉，Sentinel 定期去對方的 TAXII 伺服器取指標，像訂報紙。上傳 API 是推，你的 TIP 或指令碼主動送進來，像投稿。MDTI 連接器是微軟直送，啟用就有。

曉臻：考題怎麼認關鍵字？

雲哲：題幹出現 API 根 URL 加集合 ID，這兩個名詞幾乎只在 TAXII 出現，答案就是 TAXII 連接器。出現 MISP、自家 TIP、推送、或應用程式註冊，就是上傳 API。

曉臻：上傳 API 要準備什麼權限？

雲哲：Entra 應用程式註冊，再授與工作區的 Microsoft Sentinel Contributor 角色。它送 STIX 2.1 物件，除了指標還能送威脅執行者、攻擊模式跟關係。舊的 Graph tiIndicators 已淘汰，看到當干擾項。

曉臻：最大的陷阱是什麼？

雲哲：題目給的是內部業務清單，像 VIP、離職員工、允許的掃描器 IP。那不是威脅情報，正解是 watchlist。別被清單兩個字騙去選 TI 匯入。

曉臻：那 MDTI 本身是什麼定位？

雲哲：微軟自家的情資工廠。四樣東西要認得：情資文章附現成 IoC；intel profiles 是威脅執行者的檔案卡；Intel explorer 是網際網路地圖，查 passive DNS、WHOIS 跟憑證；Intel projects 給團隊共用指標。

曉臻：標準版跟進階版差在哪？

雲哲：標準版免費，開放來源情資加有限的文章。進階版要授權，解鎖完整文章庫、全量 IoC，還有最值錢的網際網路資料集。

曉臻：MDTI 跟 Sentinel 的威脅情報管理怎麼分工？

雲哲：一句話：MDTI 是情資的生產者跟百科，Sentinel 情報管理是你家情資的營運中心。題目問查某網域的歷史解析、關聯基礎設施，選 MDTI；問把 ISAC 指標拿來比對記錄、加標籤設失效，選 Sentinel。

曉臻：干擾項會放什麼？

雲哲：常放 Defender XDR 的 threat analytics。它講的是微軟追蹤的活動對你組織的曝險，不是可查詢的網際網路資料集，方向不一樣。

曉臻：第三個重點。指標進來以後落在哪？

雲哲：新表是 ThreatIntelIndicators，觀測值放在 ObservableKey 跟 ObservableValue；其他 STIX 物件放 ThreatIntelObjects。舊表 ThreatIntelligenceIndicator 已在退場時程，新舊名字都認得。

曉臻：查新表有什麼標準起手式？

雲哲：同一個指標更新會多一列，所以要用 summarize arg_max 依 Id 只留最新版本，再過濾 IsActive 為真、ValidUntil 還沒過期。拿過期指標去比對就是誤判製造機。

曉臻：比對的規則哪裡來？

雲哲：內容中樞的 Threat Intelligence 解決方案帶了 TI map 系列範本，命名規律是拿哪種指標對哪張表，像 TI map IP entity to CommonSecurityLog，背後就是把有效指標 join 上記錄表。

曉臻：這裡最愛考的陷阱是？

雲哲：兩邊都要有資料。指標有了、對應的記錄表沒接，規則就是空轉。所以環境有什麼表才開什麼規則。另外微軟還有一條內建的 Matching Analytics，自動拿微軟指標對 CEF、DNS、Syslog 比對。

曉臻：換 watchlist。它跟威脅情報的分工是？

雲哲：威脅情報處理外面的壞東西，watchlist 處理你自己知道的事：VIP 名單、離職員工、允許的掃描器 IP。這些業務脈絡不會出現在任何情資餵送裡，但少了它們偵測就又聾又瞎。

曉臻：建立的時候要設哪三件事？

雲哲：名稱、別名、SearchKey。別名是 _GetWatchlist 括號裡那個字串；SearchKey 是你最常拿來 join 的欄位，引擎會針對它最佳化。上限記一下：精靈上傳 CSV 約 3.8 MB，更大要走儲存體加 SAS 的路徑。

曉臻：怎麼用進規則？

雲哲：用 _GetWatchlist 加別名把清單當表用，跟 SigninLogs 做 inner join，非 VIP 的失敗登入全濾掉。它是寫在分析規則的 KQL 裡，沒有獨立的 watchlist 規則類型。

曉臻：它最大的好處是？

雲哲：清單內容跟偵測邏輯解耦。名單在 UI 隨時增刪改，規則一個字都不用動。

曉臻：快問快答，三題。第一題：ISAC 提供 TAXII 2.1 服務，給了 API 根 URL 跟集合 ID，怎麼匯入？

雲哲：設定 TAXII 連接器建立長期訂閱，填 API 根 URL、集合 ID、帳密跟輪詢頻率，之後更新自動進來。

曉臻：第二題：TI map IP 規則開了三天完全沒警示，最可能的原因？

雲哲：缺了另一半。指標有進來，但對應的記錄表沒資料，規則就是空轉。先確認 CommonSecurityLog 這種目標表真的有在收。

曉臻：第三題：法務要求對三百位 VIP 的登入失敗降低告警門檻，而且分析師要能自己維護名單，用什麼？

雲哲：watchlist，用 _GetWatchlist 進規則。這是內部清單不是威脅指標，也不用建自訂表——watchlist 免擷取管線又能在 UI 編輯。

曉臻：三題都答得很乾淨。明天預告？

雲哲：明天是第二週最後一天，也是 2026 考綱最新的一塊：Sentinel data lake 雙層架構、summary rules 跟 KQL jobs，長期保留跟低成本比對的解法都在那裡。

雲哲：明天見！

EP10 · P1-W2-5 · 7:37
Sentinel data lake 與 Summary Rules
展開逐字稿

曉臻：哈囉大家好，歡迎回到 SC-200 速成電台，我是曉臻。第二週最後一天，今天這集聽說是整份新考綱裡最新的一塊？

雲哲：我是雲哲。對，Microsoft Sentinel data lake。它要解 SOC 的老難題：偵測要即時、資料要留得久、帳單要付得起，過去只能三選二。

曉臻：老規矩，三個今日重點。

雲哲：第一，分析層跟資料湖層的雙層架構，還有資料該進哪一層。第二，lake 的三種打開方式，重點在 KQL jobs。第三，summary rules，還有跟 search jobs 的三選一比較，這題考試最愛。

曉臻：先給個生活比喻吧。

雲哲：想成廚房。分析層是冰箱，常開常拿、隨手就用，但空間貴。lake 層是冷凍庫，便宜、能塞、放得久，只是要吃之前多一道工序。

曉臻：兩層的成本模型差在哪？

雲哲：分析層按 GB 擷取計費，查詢不另計費。lake 層是低價擷取加儲存費，但查詢、jobs、筆記本按用量計費，所以 lake 查詢要記得收窄範圍。

曉臻：保留期呢？

雲哲：分析層是互動保留，Sentinel 資料表含 90 天；lake 的總保留最長 12 年。合規要留三年、五年的資料，家在這裡。

曉臻：最關鍵的差別是不是偵測？

雲哲：對，這句一定要背：分析規則跟 NRT 規則只在分析層執行，偵測引擎根本不讀 lake。lake 裡的東西要能觸發偵測，只能靠 KQL jobs 升階，或 summary rules 彙總回來。

曉臻：那我把資料放 lake，分析層不就看不到了？

雲哲：反過來有救。進了分析層的資料都會自動鏡射一份到 lake，不另收擷取費，所以 lake 永遠擁有全量；只進 lake 的不會出現在分析層。一句話：分析層管現在，lake 管全部。

曉臻：那實務上怎麼決定一張表放哪層？

雲哲：只問兩個問題：要驅動即時偵測嗎？查詢頻率配得上分析層的單價嗎？登入記錄、端點事件、警示類進分析層；netflow、防火牆流量、DNS、純合規保留的進 lake。

曉臻：考題怎麼認關鍵字？

雲哲：看到 real-time detection、分析規則要用，就是分析層，沒有第二個選擇。看到 high volume、rarely queried、合規保留、成本最小化，就是 lake 層。

曉臻：陷阱選項通常長什麼樣？

雲哲：兩個極端。全部進分析層再調高承諾層級，付不起、違反成本要求；全部進 lake，偵測直接斷炊。記住雙層不是二選一，是各司其職。

曉臻：好，冷凍庫裡的資料怎麼吃？

雲哲：三條路。lake exploration 是在 Defender 入口對 lake 資料表下互動 KQL，適合臨時查證；Jupyter 筆記本用 Python 加 Spark 做大規模分析；第三條就是 KQL jobs。

曉臻：互動查詢有什麼典型場景？

雲哲：回溯獵捕的起手式。像去年九月有沒有主機解析過某個可疑網域，資料早超出分析層的互動保留，在 lake 上不必還原就能直接查。記得用 between 收窄時間窗。

曉臻：什麼時候要升級成 KQL job？

雲哲：當你需要定期在湖裡撈東西，而且撈到的要能觸發偵測。job 支援完整 KQL，join、summarize 都可以，跑完把結果升階寫回分析層的自訂表。湖裡撈到的魚，放回冰箱才能上菜。

曉臻：它的考試指紋？

雲哲：三個條件同時出現就是它：lake 資料、排程或定期、結果要供分析規則使用。少了定期就是一次性 job 或 search job；少了餵偵測，互動查詢可能就夠了。

曉臻：第三個重點，summary rules 又解決什麼？

雲哲：另一半問題。防火牆、netflow 每天數百 GB，就算進了 lake，偵測跟儀表板還是需要一個即時可查的統計面。summary rule 以固定 bin 持續跑彙總查詢，把結果寫進分析層的自訂表。

曉臻：bin 可以設多久？

雲哲：20 分鐘到 24 小時。比方每小時把防火牆連線壓成一列，算連線數、deny 數、傳輸量，寫進 FirewallSummary_CL。之後分析規則直接對這張輕量表寫，deny 數超過 500 就告警。原始洪流留在低成本層，量級常差一百倍。

曉臻：那 summary rules 跟 KQL jobs 怎麼分？

雲哲：一個向前看、一個向後看。summary rules 是持續進行式，資料一邊進來一邊濃縮，服務日常偵測跟儀表板；KQL jobs 是回頭看，對湖裡的歷史做一次或排程分析，服務回溯獵捕。

曉臻：第三兄弟 search jobs 呢？

雲哲：非同步的大範圍搜尋，KQL 受限、以篩選為主，結果落在結尾 _SRCH 的資料表。三句話收：summary rules 是濃縮果汁、KQL jobs 是定時撈魚、search jobs 是大海撈針。

曉臻：三選一有沒有裁決順序？

雲哲：先抓訊號詞。持續、每小時彙總、供儀表板長期使用，選 summary rule；歷史加排程又要餵偵測，選 KQL job；一次性撈某個 IP 的記錄、不需複雜查詢，選 search job。

曉臻：兩個高頻陷阱提醒一下。

雲哲：第一，把 search job 選給需要 join 的複雜歷史分析，它的 KQL 受限，正解是 KQL job。第二，把 summary rule 選給回掃過去六個月，它只從啟用後往前彙總，回不了頭。

曉臻：還有沒有舊詞彙要對映？

雲哲：auxiliary logs 往低成本層歸類，接入 lake 之後資料就存在 lake 層。傳統 archive 加 restore 是舊解法，要先還原才查得到；題幹標明已接入 lake，直接查湖幾乎都是正解。

曉臻：有前提條件嗎？

雲哲：有，data lake 建在 Defender 入口網站的統一平台上，工作區要先連進 Defender 入口才接得上。所以考綱才把入口統一跟 data lake 綁在同一波更新。

曉臻：快問快答，三題。第一題：每天 300 GB 防火牆記錄，法遵要留 12 個月，SOC 只對連線統計做偵測，怎麼設計？

雲哲：防火牆表設 lake 層、總保留 12 個月，再建 summary rule 每小時彙總寫進分析層的 _CL，偵測跟活頁簿都對摘要表做。

曉臻：第二題：情資發布新的 C2 清單，要回掃湖裡 180 天，命中還要能開分析規則？

雲哲：排程 KQL job，跑完把結果升階回分析層自訂表再開規則。不能選 summary rule，它只向前彙總、回不了頭。

曉臻：第三題：法遵要求調出某個 IP 十二個月內的全部原始記錄，一次性、不必複雜查詢？

雲哲：search job，結果落在 _SRCH 資料表直接交件。要注意它的 KQL 受限，要 join 的話還是得換 KQL job。

曉臻：三題都答得很準，第二週到這裡收工。下週開場是什麼？

雲哲：下週第一天講 Microsoft Security Copilot 的設定與管理：standalone 跟 embedded 兩種體驗、SCU 容量跟 overage、外掛跟 promptbook，還有會自主分診的 agents。

曉臻：哈囉大家好，歡迎回到 SC-200 速成電台，我是曉臻。昨天守住了裝置，今天戰場搬到哪？

雲哲：我是雲哲。搬到信箱。壓倒性多數的入侵都是從一封釣魚郵件開始，所以 D2 裡 MDO 有一塊獨立戰區。昨天 MDE 是裝置的急診室，今天 MDO 就是信箱的急診室。

雲哲：第一，EOP、Plan 1、Plan 2 三層保護誰有什麼。第二，用 Threat Explorer 追出一波 campaign，再選對修復動作跟權限。第三，ZAP 跟 AIR 兩個自動化幫手，還有租用戶允許封鎖清單。

曉臻：EOP 是要另外買的嗎？

雲哲：不用，只要信箱在 Exchange Online 就內建。它做郵件流過濾：連線過濾、反垃圾、反惡意程式碼、基本反釣魚，還有隔離區跟 ZAP。

曉臻：Plan 1 加了什麼？

雲哲：兩個招牌：Safe Attachments 跟 Safe Links，再加 SharePoint、OneDrive、Teams 的檔案防護，還有即時偵測。

曉臻：Safe Attachments 的原理是？

雲哲：附件在送達前先丟進虛擬沙箱引爆，看實際行為而不是只比對特徵碼，專抓零時差惡意附件。政策動作有 Monitor、Block，還有 Dynamic Delivery。

曉臻：Dynamic Delivery 在幹嘛？

雲哲：先把信件本文送給收件者，附件掃完再補上，兼顧安全跟收信速度。

曉臻：那寄達時就掃過連結了，Safe Links 為什麼還要在點擊時再檢查一次？

雲哲：因為攻擊者會玩延遲武裝。寄信時 URL 指向乾淨頁面，通過過濾之後幾小時才換成釣魚頁。所以 Safe Links 改寫 URL，在點擊當下再驗一次，防護還延伸到 Teams 跟 Office 應用程式裡的連結。

曉臻：Plan 2 呢？

雲哲：調查與回應那一整套：Threat Explorer、Campaign Views、AIR、攻擊模擬訓練，還有進階搜捕的郵件資料表。

曉臻：功能歸屬題怎麼答？

雲哲：記兩組。即時偵測是 Plan 1 的縮水版查詢工具，Threat Explorer 是 Plan 2 專屬。看到 campaign views、AIR、攻擊模擬、EmailEvents 資料表，一律 Plan 2。

曉臻：有沒有經典陷阱？

雲哲：有：沒加購 MDO，能不能自動移除已送達後才被判定的信？可以，ZAP 是 EOP 內建功能，人人都有。

曉臻：進第二個重點。Threat Explorer 怎麼用？

雲哲：它是郵件的 X 光機，看得到全組織的郵件流向，資料回溯最長 30 天。實戰是一條固定漏斗，四步。

曉臻：第一步？

雲哲：從已知線索撈同類。拿到一封回報的釣魚信，用寄件者位址、寄件網域、主旨關鍵字、URL 網域或附件 SHA256 去篩，把同一波全撈出來。

曉臻：第二步是判讀流向？

雲哲：看兩個欄位。傳遞動作有 Delivered、Junked、Blocked、Replaced；最新傳遞位置有收件匣、垃圾郵件、隔離區、已刪除郵件。之所以叫最新，是因為 ZAP 或管理員動作可能已經事後搬過。

曉臻：第三步、第四步呢？

雲哲：鎖定高風險集合：已傳遞而且還在收件匣的就是待修復對象，再交叉 URL 點擊檢視，找出不只收到還點了的人優先處置。最後在 Explorer 勾選郵件、按採取動作。

曉臻：單封信要深入看什麼？

雲哲：用電子郵件實體頁面。它彙整傳遞路徑、完整標頭跟 URL 引爆結果。標頭抓兩塊：反垃圾郵件報告裡的 SCL 跟 CAT 判定類別，還有驗證結果裡的 SPF、DKIM、DMARC 跟複合驗證。

曉臻：CAT 有哪些值要認？

雲哲：PHSH 是釣魚、HPHSH 是高信賴度釣魚、MALW 是惡意程式碼、SPOOF 是詐騙、BULK 是大量郵件。驗證全掛的合作夥伴來信，多半就是偽冒。

曉臻：Campaign Views 幫我省掉什麼？

雲哲：省掉自己拼圖。它用機器學習把同一攻擊行動的郵件聚合成一個 campaign，一頁給你時間線、寄件 IP 與網域、用到的 URL、多少人收到、多少人點擊。

曉臻：想用 KQL 做同一件事呢？

雲哲：Plan 2 才有郵件資料表。從 EmailEvents 撈，NetworkMessageId 是跨郵件資料表關聯的鑰匙，再 left join 到 EmailPostDeliveryEvents。沒有比對到的信，就是還躺在信箱裡的修復對象。

曉臻：撈到之後，修復動作怎麼選？

雲哲：五種。移至垃圾郵件跟移至刪除的郵件，使用者自己搬得回來；soft delete 進可復原刪除項目，還救得回；hard delete 是永久清除；還有誤判後把信移回收件匣。

曉臻：預設該選哪一個？

雲哲：釣魚修復的預設選擇是 soft delete，清出信箱又保留還原跟存證餘地。惡意程式碼或法遵要求徹底移除，才走 hard delete。判斷句型很直白：題幹說使用者必須能復原就 soft，說必須不能復原就 hard。

曉臻：權限這塊有什麼坑？

雲哲：執行或核准這些修復要 Search and Purge 角色，它屬於 Defender 入口的電子郵件與共同作業權限體系，預設含在 Data Investigator 跟 Organization Management 裡。

曉臻：所以有 Security Administrator 不夠？

雲哲：不夠，那些 Entra 角色不會自動附帶 Search and Purge，Security Reader 更是只能看。看到問要什麼額外權限才能清除郵件，答案幾乎都是它。

曉臻：第三個重點，ZAP 跟 AIR 差在哪？

雲哲：ZAP 是自動反悔：信送達之後情報更新、發現它其實是壞的，就回頭把信搬走，垃圾郵件移到垃圾郵件匣，釣魚跟惡意程式碼移進隔離區，全程無人參與。

曉臻：AIR 呢？

雲哲：Plan 2 的調查助理，由警示觸發或分析師手動發動。它以那封信為根找出相似郵件、圈出受影響使用者、查誰點了誰轉寄了，最後產出建議動作。

曉臻：AIR 會自己刪信嗎？

雲哲：不會，這是考點。建議全部送進動作中心，等有 Search and Purge 權限的人核准。一句話分工：ZAP 是單封信層級的自動反悔，AIR 是事件層級的自動調查、人工核准。

曉臻：最後是允許封鎖清單？

雲哲：租用戶允許封鎖清單可以封鎖網域與位址、偽冒寄件者、URL、檔案雜湊跟 IP，封鎖在郵件流當下就生效，不必等它進信箱再清。

曉臻：允許為什麼不能直接加？

雲哲：因為允許是高風險操作，設計上刻意不順手。多數類型要透過提交流程回報誤判，系統確認後才建立暫時性允許項目，預設 30 天，讓它自動過期才不會累積成永久後門。

曉臻：優先序有幾條鐵律？

雲哲：三條。封鎖永遠贏過允許；惡意程式碼跟高信賴度釣魚的判定不能被一般允許蓋過；要放行誤判，正規解是經由提交建立允許項目。

曉臻：快問快答，三題。第一題：一波釣魚信 58 封還在收件匣，法務可能要調原信，選哪個修復動作？

雲哲：批次 soft delete，信進可復原刪除項目，需要時救得回來。而且你要有 Search and Purge 才按得下去，動作進度在動作中心追蹤。

曉臻：第二題：使用者已經把寄件者加進安全寄件者清單，信還是進隔離區，為什麼？

雲哲：高信賴度釣魚的判定壓過使用者層級的允許，安全寄件者清單救不出來。要放行就由管理員提交誤判，建立租用戶層級的允許項目。

曉臻：第三題：郵件自己消失、沒有任何人核准，是誰做的？

雲哲：ZAP，而且它是 EOP 內建。如果描述是系統列出相似郵件跟受影響使用者、等待核准，那就是 AIR。

曉臻：三題都答得很乾脆。明天預告？

雲哲：明天換身分威脅：攻擊者拿到帳號之後在網域裡做什麼、MDI 怎麼看橫向移動，還有身分風險怎麼判讀跟回應。

曉臻：信箱守好了，明天守身分。我們明天見！

雲哲：明天見！
